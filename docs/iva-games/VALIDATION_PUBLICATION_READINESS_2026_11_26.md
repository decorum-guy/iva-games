## Изменения перед выпуском

1. [`c259bdc`](https://github.com/decorum-guy/iva-games/commit/c259bdcd91fbeb80c0daf5d0ff24401058d5f33c) устраняет общий IP-бюджет всех посетителей за Caddy. Платформа и оба шахматных сервера принимают `X-Iva-Client-IP` только от точного настроенного socket IP, а Caddy перезаписывает этот заголовок. Без доверенного peer подмена не работает. Compose получает статический адрес proxy из той же переменной, что и доверенные адреса приложений; динамический пул исключает этот адрес. [Контракт и ограничения](TRUSTED_PROXY.md).
2. [`9e36f56`](https://github.com/decorum-guy/iva-games/commit/9e36f562b93313246f34a25c1bf314eb2dee22e0) открывает каталог без входа: `/` — выбор раздела, `/chess` — REMORSE и Форсаж, `/games` — остальные игры. Добавлена классификация реестра `collectionId`; статус готовности общего комнатного runtime не подменён гостевой ссылкой. Старые hash-ссылки, приглашения, вход, подтверждение и сброс пароля сохраняются. В CI добавлены настоящие браузерные регрессии каталога и проверка конфигураций Compose/Caddy.
3. [`4a86989`](https://github.com/decorum-guy/iva-games/commit/4a86989516b9842a58dd3a13beefc374893f1df4) исправляет найденное браузером переполнение пустого списка комнат при сильном увеличении. Кнопка «Создать первую комнату» переносит текст и ограничена шириной контейнера; заголовок и действие на узком экране расположены вертикально. Строгая проверка ширины и доступности контролов сохранена, горизонтальное переполнение не маскируется скрытием содержимого.

## Граница готовности

В принятых проверках не осталось падающих сценариев. Исходники и пакет первого размещения подготовлены; публичный сервер этим отчётом не объявляется работающим. Для завершения выпуска нужны:

- Фактический VPS, IP и SSH, проверка существующих служб и совместимости частной Docker-подсети.
- DNS для `iva-games.pro` и `chess.iva-games.pro`, действующий HTTPS и публичная проверка двух независимых клиентов.
- Настоящие SMTP-реквизиты и отправитель. Production не стартует с пустыми реквизитами; healthcheck не подтверждает доставку. Подтверждение почты и сброс пароля нужно принять на согласованном реальном получателе.
- Постоянные volumes на выбранном сервере и реальная проверка backup → новая база/volume → восстановление. Проверка замены контейнера не заменяет восстановление резервной копии.
- Настройка автоматического обновления после push с фактическим registry/сервером, проверкой CI, backup и откатом. Нынешние workflow только проверяют и собирают код; deploy на push пока не реализован.

Telegram остаётся отключённым и не блокирует гостевые шахматы или приглашения на сайте. Для его включения отдельно требуются выделенный бот, секреты, HTTPS/webhook и проверенный маршрут через `kz-bot`; реальные сообщения — только заранее разрешённому получателю. Сохранённые свидетельства доступа с Mac не означают доступ из будущего игрового контейнера.

Покупка домена и планы хостинга известны из сообщения владельца. DNS этим проходом не изменялся, текущий публичный сайт не принимался. Main/PR не сливались; все изменения публикуются обычными последовательными коммитами в PR №9.
