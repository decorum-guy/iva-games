## DNS и почта

В зоне `iva-games.pro` владелец меняет `A @` и создаёт `A chess`, обе на `78.137.109.13`. На тех же именах не должно оставаться старых A, CNAME или AAAA. Глобальный IPv6 для данного VPS не настроен. DNS у регистратора не редактировался.

Настройки существующего SMTP для проекта не найдены. Нужны `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, разрешённый `SMTP_FROM` и, если провайдер требует авторизацию, `SMTP_USER` и `SMTP_PASSWORD`. Вводить их в root-owned файл по SSH через `ssh -t iva-games sudoedit /etc/iva-games/platform.env`. Формат `KEY=value`, без shell-кавычек. Значения SPF, DKIM и при необходимости записи верификации или Return-Path берутся из панели выбранного SMTP-провайдера. `TEST_EMAIL` опционален и нужен только для разрешённой проверки доставки. `TELEGRAM_ENABLED=false`.

```bash
ssh -t iva-games 'sudo cat /var/lib/iva-games/activation/state.json'
ssh -t iva-games 'sudo systemctl list-timers iva-games-activate.timer --no-pager'
ssh -t iva-games 'sudo journalctl -u iva-games-activate.service -n 30 --no-pager'
```

`iva-games-activate.service` и таймер установлены в systemd. После перезагрузки журнал подтвердил повторные запуски примерно раз в минуту. Таймер сверяет два последовательных результата от двух резолверов, затем проверяет SMTP по TLS без отправки письма, Compose и внутренний health. Caddy стартует после этих проверок. После `WAITING_TLS` проверяются три HTTPS health-ответа с системным доверием к сертификату. Состояние `ACTIVE` отключает таймер первого запуска. Тесты с подменой DNS покрывают старый или смешанный адрес, один готовый домен, ошибку резолвера, неверную AAAA и сброс последовательности. Проверка повторных проходов `WAITING_TLS` и `ACTIVE` выполнена тестами с подменой зависимостей.

## Копии и обновления

Снимок `/srv/iva-games-backups/preflight-20261126T121520Z` содержит две отдельные пары SQLite. У шахмат снята копия рабочего приватного volume. У портала проверен отдельный volume с тем же образом, анонимной сессией и отключённой сетью, поскольку production SMTP ещё отсутствует. Обе пары восстановлены в новые `iva-games-restore-chess-initial` и `iva-games-restore-platform-initial`. Запущены изолированные приложения, проверены health, SQLite integrity и внешние ключи. Сессия портала пережила восстановление, аккаунтов в этой копии нет. На Mac экспортирован архив в `~/Library/Application Support/Iva Games VPS/backups` под FileVault с правами 0600, сверены 13 SHA-256.

Для повторной проверки из резервной копии на VPS выбрать новое уникальное имя volume. Образы по digest должны присутствовать локально.

```bash
sudo /opt/iva-games/deploy/restore-check.sh \
  /srv/iva-games-backups/preflight-20261126T121520Z/chess iva-games-restore-chess-recheck
sudo /opt/iva-games/deploy/restore-check.sh \
  /srv/iva-games-backups/preflight-20261126T121520Z/platform-isolated iva-games-restore-platform-recheck
```

GitHub environment `production` ограничен `main`. После успешного CI workflow заново проверяет и публикует фактические образы с SHA. На VPS ключ CI вызывает только фиксированную процедуру `iva-deploy`; личный ключ Mac остаётся на Mac. При первом выпуске процедура загрузила ровно закреплённые digest и сохранила их в `/etc/iva-games/pins.json`. До `ACTIVE` другие SHA откладываются. После `ACTIVE` изменившиеся сервисы обновляются под тем же lock, с резервной копией перед обновлением и проверкой HTTPS. При совместимости допускается откат образа с сохранением текущих томов. При сбое не подменять их старой копией. Оператор проверяет `/var/lib/iva-games/activation/pending.json`, `deploy-error.json` и состояние сервисов перед ручным продолжением.

Штатная публикация образов и ответ `STAGED` подтверждают реестр образов, ключ CI, политику допуска релиза и транспорт до VPS. В отдельной проверке CI-ключ получил отказ в TCP forwarding и в запуске произвольной команды. Другой SHA до `ACTIVE` получил `DEFERRED`. Контролируемое обновление работающего сайта и браузерные проверки обеих игр, аккаунтов и сетевых сценариев остаются после первого HTTPS.
