# Iva Games — доступ к kz-bot и Telegram

## Основание

25 ноября 2026 года владелец прямо поручил использовать существующий сервер-прокси `kz-bot` для Telegram-бота Iva Games и проверять наличие SSH-доступа при локальной разработке. Источник инфраструктурных сведений: [Artem Control Center, docs/INFRASTRUCTURE_ACCESS.md, commit 4621ab0](https://github.com/decorum-guy/artem-control-center/blob/4621ab0979b75af37eca0aa46736c0f4e3071c24/docs/INFRASTRUCTURE_ACCESS.md). Этот файл прочитан; настройки панели и её сервисов не менялись.

Из источника подтверждено назначение: `kz-bot` — отдельный исходящий зарубежный прокси, используемый Telegram-ботом на `ha-vps`. Владелец сообщил о восстановлении узла 24 ноября. Это сообщение, а не проверка текущей доступности. Протокол прокси, порт и credentials из одного SSH alias определить нельзя.

## Обязательная локальная проверка

В корне Iva Games:

```sh
npm run check:kz-bot
```

Скрипт выполняет ограниченную проверку SSH-конфигурации и, если alias настроен, read-only подключение с `BatchMode`, коротким timeout и обязательной проверкой известного host key. Он не создаёт ключи или туннели, не меняет службы и не печатает hostname, логин, пути ключей либо proxy credentials.

Если в окружении задан `TELEGRAM_PROXY_URL`, дополнительно проверяется HTTPS-доступ к корню `api.telegram.org` через этот прокси. Bot token не нужен, сообщения не отправляются. Секреты прокси передаются curl через stdin; в аргументы процесса не попадают. `NO_PROXY` не может незаметно переключить эту проверку на прямой маршрут.

Результаты разделены: SSH, исходящий proxy route и фактическая доставка ботом. Успешный HTTPS-запрос не доказывает действительность токена или получение приглашения человеком. Код возврата 2 означает, что хотя бы одна инфраструктурная часть не подтверждена; это не блокирует независимые локальные проверки аккаунтов и комнат.

В облачной среде текущей разработки проверка дала `ssh=configuration_unavailable`, `proxy=not_configured`. Доступ Mac владельца этим не опровергнут. Локальному исполнителю следует использовать уже настроенный alias, а не создавать доступ заново. Не отключать проверку host key и не копировать приватные ключи в задачу, логи или Git.

## Подключение транспорта

`packages/telegram-transport` принимает конкретный `proxyUrl` и отказывается создавать транспорт без него. Поддерживаются `http://` и `https://` для CONNECT, `socks5h://` для SOCKS5 с разрешением имени назначения на прокси. Фактический URL должен быть получен из существующей разрешённой конфигурации; здесь адрес и порт не выдуманы.

Транспорт не использует общий системный proxy автоматически и не пробует прямую отправку при ошибке. Адрес назначения фиксирован как HTTPS Telegram Bot API. Ошибки возвращаются без токена, URL и credentials. Таймаут после отправки обозначается `DELIVERY_UNKNOWN`, а не обещанием, что сообщение не доставлено.

Транспорт подключён к пользовательской привязке и очереди в `apps/platform/src/main.ts`, но включается только через полную явную серверную конфигурацию. Перед каждой отправкой очередь проверяет актуальность приглашения, opt-in, блокировки и версию привязки по [TELEGRAM_LINKING.md](TELEGRAM_LINKING.md). Подготовленный код и mock-тесты не подтверждают внешнюю активацию бота или доставку через реальный прокси. Настройки перечислены в [README сервера](../../apps/platform/README.md) и [.env.platform.example](../../.env.platform.example).

Не создавать параллельный прокси, не менять существующего потребителя на `ha-vps`, не использовать токен другого проекта и не добавлять рассылки. В пользовательские настройки Iva Games не выводить SSH/сетевые реквизиты.
