# Аккаунт Iva Games через Telegram

В production действует `MAIL_MODE=disabled`. Каталог и гостевые шахматы могут открываться до подключения бота. Новые аккаунты и последующий вход используют одноразовый код в личном чате. Если Telegram не настроен, сайт показывает гостевой вход в шахматы. Действующие локальные демонстрации, тесты и самостоятельные установки могут использовать прежнюю явно настроенную почту.

## Вход и друзья

1. Посетитель нажимает «Продолжить через Telegram», открывает бота и нажимает «Старт». Код вводится в том же браузере. При первом входе сайт запрашивает уникальное `@имя` и отображаемое имя.
2. Сайт ищет игроков по `@имени` и отправляет заявки. Обе стороны видят состояние на сайте. Бот показывает профиль, список друзей и входящие заявки по `/profile`, `/friends` и `/requests`. Принятие и отклонение используют ту же запись и проверку прав, что и на сайте.
3. Аватар по умолчанию показывает инициалы. В профиле сайта или бота можно сохранить одну из шести фигур. Она видна в профиле, списках друзей, заявках и комнатах. В боте `/name Новое имя` меняет отображаемое имя, а `@имя` сохраняется.

Браузерная попытка живёт десять минут, привязана к созданной сервером сессии и ограничена пятью неверными кодами. Для доставки принимается только личный `/start` от владельца чата. Код выводится из отдельного закрытого ключа и привязан к попытке и Telegram user ID. В SQLite сохраняется связь с неизменяемым числовым Telegram ID, поэтому смена имени в Telegram не создаёт новый профиль. Повтор принятия заявки идемпотентен.

## Подключение на Mac

Используйте отдельного бота из BotFather. Скрипт `deploy/iva-games/telegram-auth-setup-mac.py` запрашивает токен скрыто, проверяет бота и регистрирует webhook `https://iva-games.pro/integrations/telegram/auth-webhook`. Для Mac используется проверенный временный SSH-туннель к Telegram Bot API через существующий `kz-bot`. Mac проверяет TLS до передачи токена. Туннель использует учётную запись `kz-bot` на обоих маршрутах, с промежуточным SSH через `ha-vps` или напрямую. Корневой помощник `configure-telegram-auth.py` пишет настройки вне checkout, под общим lock пересоздаёт только platform и сверяет доступность Telegram-входа локальным запросом.

На VPS хранятся ID и имя бота, секрет webhook и ключ формирования кодов. Токен BotFather в среду VPS не передаётся. Telegram выполняет ответный метод Bot API из ответа на webhook. Для этого режима runtime не нужна исходящая связь с Telegram. Входящие заявки открываются по команде бота. Режим уведомлений о приглашениях старой интеграции отдельно зависит от своего транспорта.

## Автообновление

После успешного CI пуш в `main` может обновить портал и шахматы. Публикация двух образов в GHCR и допуск SHA проходят в [.github/workflows/iva-release-check.yml](../../.github/workflows/iva-release-check.yml). На VPS сравниваются входы сборки, поэтому изменение только платформы сохраняет прежний chess digest. REMORSE и Форсаж находятся в общем chess-контейнере. Для отдельного обновления игр потребуются отдельные единицы публикации. Новая игра в отдельной ветке или каталоге становится частью автодеплоя после добавления её в runtime, каталог, маршрутизацию и проверки соответствующей единицы публикации. [Архитектура выпуска](ARCHITECTURE.md#автоматическая-публикация).

Перед первым `ACTIVE` право на подготовку имеет только SHA, который администратор закрепил в `activation.json`. DNS по-прежнему проверяется через два независимых резолвера два раза подряд. SMTP проверяется только при явно выбранном `MAIL_MODE=smtp`.
