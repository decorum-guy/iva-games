# Подключение существующей сети шахмат к Iva Games

## Состояние

Это контракт следующей интеграции, **не подтверждение подключённых шахмат**. Во время реализации платформы другой агент завершает шахматы и их перенос. Общая платформа не меняет гостевую авторизацию, URL, WebSocket-протокол, сохранения или исходники этих игр. В каталоге Remorse и Форсаж имеют `unavailable`, пока фактический адаптер не зарегистрирован и не проверен.

`GameRuntime` в `packages/session-kit/src/types.ts` предоставляет четыре операции: `createMatch`, `viewForPlayer`, `applyAction`, `status`. Та же граница уже используется исполняемой проверочной партией. Аккаунты, дружба и website-приглашения принадлежат платформе; правила и допустимость хода принадлежат шахматному серверу.

## Что должен сделать адаптер

1. Принять серверную команду старта с уникальным `startCommandId`, закреплёнными rules/content versions и окончательным составом. Зафиксировать отображение `roomId платформы → matchId шахмат` и `participantId/playerId → сторона и собственная серверная идентичность`. Браузер не выбирает чужую сторону или guest identity.
2. Повтор команды возвращает ту же партию. Если процесс остановился после создания шахматной комнаты до ответа платформе, восстановление использует сохранённое отображение, а не создаёт вторую комнату.
3. Получать разрешённый снимок для конкретного аккаунта через существующий серверный public/player view. Создатель комнаты не получает дополнительных игровых прав.
4. Переводить envelope `{actionId, expectedRevision, payload}` в штатную авторитетную команду шахмат. Повторы и восстановление сохраняют прежний результат; не вызывать правила на клиенте вместо серверной проверки.
5. Согласовать окончание, сдачу, ничью и повтор партии с собственной моделью шахмат. Терминальный матч не становится активным от одного обновления страницы. Новая партия получает новую идентичность.

Для начала можно встроить адаптер в доверенный серверный процесс. При отдельном игровом процессе нужен аутентифицированный внутренний канал с timeout и повтором исходной команды. При разных публичных origin отдельно реализуется защищённый browser handoff из PLATFORM_V1; произвольный `playerId` в URL или общий cookie на все поддомены не заменяют его. Этот handoff текущим кодом не реализован.

## Совместимость

- Существующие локальные партии и гостевые ссылки продолжают работать независимо от аккаунтов портала.
- Связь старой гостевой личности с новым аккаунтом не выводится из ника. Автоматического переноса рейтинга/сохранений нет.
- `supportsBots` объявляется для конкретной интеграции. Наличие шахматного локального движка не доказывает поддержку серверных bot seats.
- Платформа разрешает будущей игре до шести мест через манифест; шахматы сохраняют собственный лимит двух сторон.
- Неизвестная версия или неизвестный результат старта не разрешают переоткрыть занятый состав. Требуется поддерживаемая версия/восстановление исходного запуска.

## Приёмка адаптера

Два независимых аккаунта проходят дружбу → приглашение → вход → готовность → настоящий шахматный матч. Отдельно проверить непричастный аккаунт, повтор старта после потери ответа, обновление обеих страниц, повтор одного хода, рестарт, завершение/ничью и работу прежней гостевой комнаты. Визуальная приёмка шахмат сохраняется собственной задачей шахматного агента.
