Источник задания — PR №21, `bab999ec201c24725e17813ea30723c11431dc38`. Кандидат включает `main` с ремонтом доставки PR №22 и подсказкой комнаты PR №23. Ревизию выпуска брать из принятой вершины [PR №24](https://github.com/decorum-guy/iva-games/pull/24) и сверять с успешным CI.

## Хранение и откат

- В существующем runtime-volume появляются две таблицы `district_territorial_matches` и `district_territorial_receipts`. Прежние комнаты, `district_matches` и `district_action_receipts` обслуживает исходный адаптер.
- У новых матчей префикс `d4-`. Кандидат понимает их и настройки v0.4-комнат при любом значении флага. Старый образ умеет читать только v0.2/v0.3. После первой v0.4-комнаты безопасный срочный откат — выключить создание нового профиля через `DISTRICT_TERRITORIAL_ENABLED=false` на совместимом образе или установить исправленный образ, который продолжит читать эти матчи.
- До выпуска создать согласованную резервную копию platform и runtime SQLite с релизным манифестом. Проверить восстановление на отдельных volumes. На новом образе с выключенным флагом создать v0.3-комнату и одновременно открыть сохранённую v0.4-партию.

## Выпуск

1. Сверить принятый SHA, CI, запущенные digest и состояние доставки VPS. Проверить v0.2/v0.3 на копии целевых данных. PR №22 проходит отдельную приёмку авторизации, завершения запросов, сохранности очередей и изоляции шахмат.
2. После проверок принятого кандидата выполнить разрешённый владельцем **platform-only** выпуск через действующую доставку `main`. Использовать существующие lock, проверку происхождения и резервирование платформы. Сравнить chess image, PID, время запуска и живую сессию до и после выпуска в пределах фактически доступных средств; отсутствие такой проверки явно записать.
3. Доставка кода и включение новых комнат — два отдельных результата. Проверить приватный `DISTRICT_TERRITORIAL_ENABLED` и публичный каталог. Для включения использовать административный доступ к существующему хосту, тот же `release.lock`, отсутствие незавершённого `pending.json` и резервную копию; установить только `DISTRICT_TERRITORIAL_ENABLED=true` в приватном `platform.env`, затем пересоздать только `platform`. Проверить обе версии комнат, два независимых HTTPS-клиента, выбор пресета, атомарный итог и восстановление. Ограниченный CI-ключ разрешает доставку образов, но не выдаёт произвольный административный доступ. Если нужного доступа в текущем окружении нет, записать точную границу и завершить доступную проверку/публикацию без обхода ограничений.

## Локальная приёмка и запуск

```sh
npm ci
npm run check
npm run build:all
node scripts/district-territorial-browser.mjs
npx vite build --config games/district/vite.territorial-simulation.config.ts
node .qa/territorial-runner/simulate.mjs --samples=9
scripts/district-territorial-demo.sh start
scripts/district-territorial-demo.sh open
```

Демо использует `127.0.0.1:4380`, отдельные platform/runtime SQLite и отдельный профиль Chrome. `scripts/district-territorial-demo.sh stop` останавливает только это демо. Ссылку на лобби печатает команда `start`. Тренировка доступна отдельно. [Тренировка](http://127.0.0.1:4380/district-training)

- Целевые проверки находятся в `games/district/tests/territorial-{maps,news,runtime,tutorial}.test.ts`. Они покрывают отказ транзакции после обновления состояния, потерю ответа, повтор, SQLite reconnect и старые снимки. Браузерные fixtures используют временную базу.
- В итоговой матрице завершились 324 партии. Выпали все 25 семейств. Браузерные результаты получены на автоматических клиентах Mac. Оценка игры людьми, физический телефон и слуховая приёмка открыты. ### Проверки на Mac

- `npm run check` прошёл 965 тестов, прошли полная сборка, HTTP smoke и 14 браузерных тестов портала. Отдельный прогон v0.3 завершил шесть кругов через настоящий HTTP с двумя аккаунтами и сохранил результат после перезапуска. Проверки инфраструктуры на Python 3.13 прошли с восемью пропусками Docker-сценариев.
- В двух полных браузерных партиях v0.4 на «Двух берегах» участвовали два независимых аккаунта и сложный бот. Клиенты приняли реальную сделку, пережили перезапуск и увидели одного победителя и одинаковый журнал в каждой партии. Прогоны заняли 17 и 27 кругов, в них вышло 7 и 13 сообщений.
- Через два авторизованных браузера прошли 17 стадий, включая внезапный удар, отмену раннего прогноза, подтверждение, успешную инвестицию, местную вспышку, риск всего города, распространение и локализацию. Изолированный стенд взял эти этапы из настоящего ядра и сохранил их в тестовом SQLite. В матчевом DTO прогнозных списков или оценок ущерба нет. Интерфейс выделил рамкой сектор или всю объявленную зону.
- Пройдены основной урок и отдельный эпизод защиты, затем продолжена обычная партия. Проверены мышь, клавиатура и эмуляция касания. Поле в последней сборке занимало 980×627 при 1366×768, 1051×759 при 1440×900 и 370×363 при 390×844. Скриншоты лежат в игнорируемом каталоге `.qa/district-territorial-browser`.
