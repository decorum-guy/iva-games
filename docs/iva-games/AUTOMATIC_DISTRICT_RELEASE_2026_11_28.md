# Район: текущая версия приходит с обычным выпуском main

## Основание и исходное состояние

28 ноября 2026 владелец прямо поручил убрать отдельное ручное включение новой версии игры. Обычный принятый push `main`, прошедший штатный CI и доставку, должен выбирать актуальную игру для новых комнат. Это изменяет прежний порядок поэтапной активации.

Исходный main — `573669650be25278a30f048733e171d6ed297144`. [Прочитанный deploy log](https://github.com/decorum-guy/iva-games/actions/runs/46066380267/job/140733540418) содержит `DEPLOYED` именно этого SHA. Прямые HTTPS GET подтвердили здоровье платформы, REMORSE и Форсажа; [публичный каталог](https://iva-games.pro/api/platform/v1/games) при этом возвращал `district@0.3` / `district-maps@0.2`. Это наблюдение до данной правки, не статус будущего выпуска.

Причина установлена по исходникам: `loadPlatformConfig` читал `DISTRICT_TERRITORIAL_ENABLED`, а entry point передавал результат в `territorialDefault`. Территориальные браузерные стенды задавали `true`; production-образ проверял наличие игры, но не её точный профиль. Поэтому успешные проверки реализации v0.4 не доказывали выбор v0.4 на существующем VPS.

## Изменение

- `apps/platform/src/main.ts` выбирает текущую территориальную регистрацию непосредственно в коде выпуска. `apps/platform/src/config.ts` больше не читает старый ключ; отсутствие переменной и оставшееся `false` не удерживают v0.3.
- `games/district/src/runtime.ts` сохранён побайтно. Его внутренний выбор регистрации остаётся полезным для исторических fixtures; он не управляется приватным env. Readers v0.2/v0.3/v0.4, сериализация, правила и шахматный код не меняются.
- Существующие лобби закрепляют `rulesVersion/contentVersion`, настройки карты и соответствующую версию бота. При старте после обновления используется их сохранённый профиль. Новые комнаты получают текущий профиль приложения.
- Актуальные территориальные стенды и демо больше не требуют `true`. Исторический парный воспроизводитель темпа сохраняет переменную для старой сравниваемой ревизии, которая ещё её читала.
- Legacy browser smoke сначала создаёт настоящую новую v0.4-комнату, затем отдельно подготавливает сохранённую v0.3 lobby через прежнюю регистрацию при остановленном тестовом сервере. После перезапуска все приглашения, настройки, старты и ходы исполняет обычный новый сервер. Ни production API, ни DTO не подменяются. Optional acceptance/showcase также используют явно историческую подготовку.

## Проверка доставки

`scripts/check-live-catalogue.mjs` берёт ожидаемые версии из настоящих constants текущего checkout. Он делает публичный GET без credentials, запрещает redirect, проверяет HTTP/JSON, доступность игры, ботов и точные rules/content. До изменения production он действительно завершился отказом: фактическая v0.3 не совпала с ожидаемой v0.4. Это проверяет обнаружение исходного разрыва.

Production image smoke запускает приложение с оставшимся `DISTRICT_TERRITORIAL_ENABLED=false` и проверяет текущий каталог до и после замены контейнера. После успешного штатного продвижения образов workflow выполняет ту же публичную проверку. `STAGED`, `DEFERRED` и вытеснённый новым main запуск не выдаются за `DEPLOYED`. `UNCHANGED` допускает повтор публичной проверки, но сам по себе не доказывает первую активацию.

Штатный SSH handler, его ограниченные credentials, release lock, backup, выборочное обновление и проверки совместимости не изменяются. Новый public check работает на CI runner; ему не требуется обновление host-скриптов или дополнительный административный доступ. Итоговые отпечатки сверены по подготовленному индексу: platform inputs изменились, platform compatibility остался прежним `4d8fa4ebe9ad3a24a5684f87f66da0ee42c5df1db7ef9ba3cb0bed183c36d5d4`; оба шахматных отпечатка совпали с исходным main. Это проверка входов доставки, не непосредственное наблюдение контейнеров VPS.

Полная локальная браузерная партия не заявляется: скачивание Chromium получило HTTP 403, а найденный launcher не имел исполняемого файла. Полные браузерные сценарии и настоящие Docker-образы проверяет обязательный CI итоговой опубликованной ревизии. Результаты его и доставки нужно читать по точному SHA; этот подготовительный отчёт не подменяет будущий `DEPLOYED`.

## Приёмка на Mac и VPS

[Самостоятельное задание локальному агенту](../../prompts/ACCEPT_AUTOMATIC_DISTRICT_RELEASE.md) включает проверку итогового CI/доставки/каталога, новой комнаты двумя разрешёнными HTTPS-клиентами, старых сохранений и фактической изоляции шахмат. При доступном обычном SSH удаление прежнего ключа из приватного env допустимо как уборка и не требует отдельного рестарта.

Ручная полная партия текущей сборки, слуховая оценка и физический телефон здесь не выполнялись. Откат сохраняет readers уже существующих матчей; возвращение к образу без поддержки записанного формата не становится допустимым из-за отмены ручного флага.
