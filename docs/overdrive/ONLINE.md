# Форсаж: сетевая игра v1

## Реализация

Форсаж использует отдельные гостевые комнаты с авторитетным Node-сервером. Оба участника отправляют команды, а сервер исполняет общий `src/overdrive/core`, сохраняет результат и рассылает одну и ту же позицию и историю. Клиент не сообщает серверу энергию, длительность формы, шах, результат партии или полученные события.

Поддержаны создание комнаты, одноразовое приглашение, выбор цвета, готовность обоих участников, все шесть приёмов, импульс и форма, обычные шахматные ходы и превращения, предложение/отказ/принятие ничьей, сдача, завершение партии и реванш со сменой цветов. Комнаты нерейтинговые, без часов. Отключение соперника приостанавливает игровые команды; сдача остаётся доступна. Истечение срока комнаты не считается поражением и не меняет шахматный результат.

REMORSE продолжает использовать прежние API, cookie и базу. Форсаж не читает и не перезаписывает его локальные сохранения или рейтинг.

## Адреса и запуск

Общий production-сервер запускается штатно:

```sh
npm run build
npm start
```

`/` отдаёт REMORSE, `/overdrive` и `/overdrive/` — отдельный `dist/overdrive/index.html`. Отсутствующий файл в `/assets/` или путь с файловым расширением получает 404, а не HTML игры.

| Назначение | Адрес |
|---|---|
| Проверка сервиса Форсажа | `GET /api/overdrive/health` |
| Получение/продление гостевой сессии | `POST /api/overdrive/guest` |
| Создание комнаты | `POST /api/overdrive/rooms` |
| Восстановление своей комнаты | `GET /api/overdrive/rooms/:id` |
| Принятие приглашения | `POST /api/overdrive/rooms/:id/join` |
| Замена ещё не использованного приглашения | `POST /api/overdrive/rooms/:id/invite` |
| WebSocket | `/overdrive-online` |

Ссылка-приглашение использует `/overdrive/#room=…&invite=…`. Параметры после `#` не передаются HTTP-серверу при открытии страницы. После присоединения `rememberRoom()` убирает приглашение из адреса. Принятый гость восстанавливает место по cookie, а не по повторному использованию приглашения.

На одном локальном адресе двум людям нужны независимые браузерные профили/контексты, чтобы иметь разные cookie. Две обычные вкладки одного профиля — один гость; новая связь с его местом замещает старую. Это проверяется и отображается явно.

## Хранение и изоляция

По умолчанию рядом с `DATABASE_PATH` создаётся отдельный файл: при `data/remorse.sqlite` это `data/remorse.sqlite.overdrive.sqlite`. Можно задать `OVERDRIVE_DATABASE_PATH` явно. Для in-memory тестов обе базы независимы. База Форсажа помечена SQLite `application_id`; попытка открыть в качестве неё существующую немаркированную базу REMORSE отклоняется.

В базе находятся хеши гостевых токенов и приглашений, места игроков, исходная и текущая позиции, полная история команд и событий, подтверждения команд, законченные партии и метаданные комнаты. Команда, новая позиция и её ACK фиксируются одной транзакцией. При восстановлении после перезапуска история повторно проигрывается общим ядром; расхождение сохранённых событий или позиции отклоняется.

Cookie `overdrive_guest` — host-only, `HttpOnly`, `SameSite=Strict`, с `Secure` при HTTPS-конфигурации. Срок гостевой сессии — 30 дней; повторное получение гостя продлевает его. По умолчанию комната без действий истекает через сутки, завершённая хранится не менее семи суток. Сервер выполняет ограниченные по размеру очистки.

Резервную копию этой базы можно делать тем же скриптом SQLite backup API, указав её путь:

```sh
DATABASE_PATH=./data/remorse.sqlite.overdrive.sqlite node server/backup.mjs ./overdrive-backup.sqlite
```

В production оба файла базы и их WAL должны располагаться в постоянном томе. `PUBLIC_ORIGIN`/список разрешённых origin должны соответствовать реальным адресам клиентов. Наличие кода не означает настройку DNS или публикацию отдельного поддомена.

## Протокол и восстановление

Протокол — `overdrive-online-v1`, правила — `overdrive-v1`. Перед командами WebSocket требует `hello` с версией и ID комнаты. Сервер проверяет cookie, принадлежность месту и Origin; приглашение само по себе не даёт произвольного доступа к чужой игре.

Каждая команда содержит ID операции, ID текущей партии и ожидаемую игровую ревизию. Повтор точно того же принятого запроса возвращает прежний ACK без нового списания энергии, хода или тика формы. Тот же ID с другим содержимым отклоняется. После реванша меняется ID партии, поэтому задержавшаяся команда старой партии не может изменить новую.

Метаданные комнаты имеют свою ревизию. Предложение ничьей дополнительно связано с отдельным ID предложения и стороной: нельзя принять собственное, уже снятое или заменённое предложение. Прямая игровая команда `agreeDraw` от клиента запрещена; сервер создаёт её только после согласия другого участника.

`OnlineRoomClient` сохраняет один неподтверждённый запрос в `sessionStorage`, ждёт полного серверного снимка при подключении, затем при необходимости повторяет исходный запрос с неизменными ID/ревизией/содержимым. Он обрабатывает потерю ACK, сетевую ошибку, перезагрузку страницы, задержавшийся ответ и обгон снимка подтверждением. Повторные подключения используют ограниченную экспоненциальную паузу с небольшим случайным разбросом. После замещения вкладки автоматический захват места обратно прекращается.

Клиент различает первое восстановление `welcome` и живые снимки `live`. Восстановление должно показывать уже достигнутую позицию без повторного проигрывания прошлых эффектов; очередные подтверждённые действия можно передавать в очередь анимаций. Сервер не зависит от длительности визуальных эффектов.

## Выполненные проверки

25 ноября 2026 года в изолированном Node-окружении прошли **38 проверок** в трёх файлах:

- `overdriveOnlineHttp.test.ts`: **14** тестов с реальным HTTP и независимыми WebSocket-сессиями. Отдельные HTML-входы и статические 404; партия из начальной позиции до мата; все шесть приёмов; форма и reconnect; закрытие/повторное открытие сервиса и SQLite; точный повтор ACK; устаревшие/конфликтующие команды; чужие Origin, cookie и протокол; имена/размер сообщений; замещение вкладки; сдача вне очереди; ничья и реванш.
- `overdriveOnlineStore.test.ts`: **6** проверок транзакционности, приглашений, отсутствия секретов в публичном снимке, истечения комнат, обнаружения повреждённой истории, разделения баз и проверки входных команд.
- `overdriveOnlineClient.test.ts`: **18** транспортных unit-тестов с управляемыми сокетами и таймерами: HTTP timeout/cancel, потерянный ACK, reload неподтверждённого запроса, синхронизация, устаревшие снимки, bounded reconnect и замещение вкладки.

После подключения нового шлюза также прошли **30** существующих HTTP/service-тестов REMORSE. TypeScript прошёл после первичной интеграции; целевой ESLint по серверу, транспортам и тестам прошёл. Точные финальные общепроектные результаты фиксируются в общем отчёте итерации.

Специальные позиции в сетевых тестах устанавливаются через внутреннее тестовое хранилище; HTTP-метода установки позиции нет. Реальная короткая партия до мата начинается со стандартной расстановки. Контролируемые транспортные тесты не заявлены как браузерная/телефонная приёмка. Данный отчёт не подтверждает активацию на Mac, физический телефон, Docker или публичный HTTPS; визуальная приёмка интерфейса выполняется отдельно.
