# Звук Форсажа: авторский банк v1

## Происхождение и назначение

Для Форсажа создан самостоятельный набор **18 готовых WAV-файлов**. Исходник — `games/overdrive/scripts/generate-overdrive-audio.py`, файлы — `games/overdrive/public/assets/overdrive/audio/`, точные SHA-256 и измерения — `manifest.json` в той же папке.

Все сигналы составлены специально для проекта из детерминированного DSP: отфильтрованный шум, негармонические резонансы керамики/металла, изменяющиеся частоты и боковые полосы механического мотора, импульсы и короткие отражения корпуса. В файлах нет записей людей, внешних аудиосэмплов, звуков REMORSE или заимствованной музыки. Это новые продуктовые ассеты проекта; их происхождение не следует описывать как скачанный CC0-пакет.

Kenney Sci-fi Sounds и Impact Sounds рассматривались при исследовании внешних вариантов. В эту поставку их файлы не включены: попытки получить пакет не дали аудиофайлов. Наличие страницы с лицензией не выдано за получение или прослушивание конкретного файла.

Художественный замысел — техническая керамика, механические замки и накопители энергии, соответствующие новой арене. Шесть приёмов имеют разную композицию и характер движения. Это описание авторского замысла; слуховая оценка человеком в этой среде не выполнена.

## Проигрывание

`games/overdrive/src/ui/audio.ts` использует готовые семплы. Runtime-осцилляторов, временных сигналов-заменителей и фонового музыкального цикла нет.

Порядок сцены: расход/активация → физический приём и взятие → превращение, если оно есть → фактический доход и заполнение ячейки → шах либо результат. Мат не сопровождается лишним отдельным сигналом шаха. Сигнал дохода не играет, когда весь доход потерян из-за переполнения. Тики срока формы тихие; окончание формы имеет отдельный звук.

Событийное расписание общее с 3D и 2D: `sceneTiming()` из `games/overdrive/src/ui/motion.ts` возвращает времена контакта, приземления, превращения, дохода и результата в миллисекундах. Плеер переводит эти значения в секунды для AudioContext. У взятия больше нет независимой постоянной задержки: при налёте звук начинается в промежуточной клетке жертвы, при обычном взятии — при приходе на клетку. Звук тарана начинается в момент контакта ладьи с целью. Превращение начинается после прихода пешки; ресурсные сигналы и шах/мат следуют за завершением этой последовательности. Reduced motion получает отдельную короткую схему от той же функции, включая краткий fade прибытия перед заменой модели.

Это синхронизация начала звукового файла по общей шкале событий, а не заявление о субъективной точности воспринимаемого удара. Аудиограф добавляет 8 мс запаса при планировании. Аппаратная задержка вывода, форма атаки внутри записи и её сочетание с реальными кадрами требуют прослушивания в браузере.

Плеер создаёт AudioContext только после `unlock()` из пользовательского жеста. `unlock()` сам ничего не проигрывает и может молча подготовить банк при включённом mute. Общая громкость относится только к этой игре. В графе есть компрессор, ограничение восьми голосов и приоритет результата над UI-кликами.

Mute, нулевая громкость и скрытие вкладки отменяют активные и запланированные голоса. События, произошедшие без разрешённого звука, не накапливаются для позднего воспроизведения. Задержавшаяся загрузка не запускает устаревший эффект. Полученные серверные снимки при восстановлении не должны передаваться в `playEvents()` как новые действия.

Публичный `stop()` отменяет сцену и очищает область дедупликации ID: его используют для новой партии, нового урока или отмены хода. Скрытие вкладки обработано внутри плеера и сохраняет дедупликацию; дополнительный вызов `stop()` снаружи для скрытия не нужен.

## Воспроизводимость и фактические проверки

Генератор запускался с Python, NumPy 2.3.5 и SciPy 1.17.0. Seed зафиксирован; в runtime эти зависимости не нужны. Повторная генерация проверяется сравнением SHA-256 всех файлов.

**17 тестов** `games/overdrive/tests/unit/overdriveAudio.test.ts` прошли: соответствие всех файлов манифесту, реальные PCM-заголовки/длительности/пики, разные файлы для всех приёмов, последовательность сцен, переполнение, дедупликация, mute/visibility, поздние загрузки, повторная загрузка после ошибки, ограничение полифонии, завершение контекста. Дополнительно проверено совпадение звуковых времён с общим планом на настоящих событиях уроков в обоих режимах движения и запланированный момент промежуточного взятия налётом. Транспортная часть использует управляемый AudioContext; она проверяет поведение кода и не является прослушиванием.

Все **18 WAV** дополнительно декодированы установленным FFmpeg с выводом в null; ошибок декодирования нет. TypeScript и целевой ESLint прошли после подключения плеера.

Попытка проверить настоящий Web Audio в headless Chromium остановилась **до открытия страницы**: окружение отклонило системный вызов `socket()` при создании браузерного профиля (`Operation not permitted`). Поэтому браузерный микс, его суммарный пик, реальное устройство вывода и субъективное звучание этой итерацией не подтверждены. Локальный воспроизводимый сценарий сохранён в `.qa/overdrive-audio/browser-check.mjs`; временные материалы в Git не включаются.

Приёмка человеком должна проверить различимость приёмов, комфорт громкости, сочетание с анимацией и устройства вывода. Эта проверка не подменена техническими измерениями.

Первичные справочные источники по используемым браузерным API: [AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume), [decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData), [AudioBufferSourceNode.start](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode/start).
