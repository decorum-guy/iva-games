# Iva Games: устройство монорепозитория

## Принятое решение

Владелец согласовал один репозиторий Iva Games: шахматная коллекция Chess 2 находится в `games/chess/`, рядом предусмотрены самостоятельные нешахматные игры. REMORSE, Форсаж, общий Engine SDK и шахматный сервер уже разделены на пакеты. Игры живут в пакетах одной ветки разработки, а не в постоянных взаимоисключающих ветках. Для задач создаются временные ветки и PR. Текущая переносимая реализация находится в `feat/overdrive-sdk`; её draft PR №3 ещё не означает слияние в `main`.

Владелец уже переименовал GitHub-репозиторий в `decorum-guy/iva-games`. Проверен неизменный repository ID `1469444922`; прежнее имя — `decorum-guy/remorse-chess`. История сохранена в том же репозитории.

## Пакеты

| Каталог | npm workspace | Владение |
|---|---|---|
| `games/chess/remorse` | `@chess-2/remorse` | Правила REMORSE, её ИИ-адаптер/оценка, обучение, сохранения, сетевой клиент, весь UI, модели, звук, auditions и профильные тесты/скрипты. |
| `games/chess/overdrive` | `@chess-2/overdrive` | То же для Форсажа: самостоятельные правила, художественная система и клиентские сценарии. |
| `packages/engine-sdk` | `@chess-2/engine-sdk` | Универсальный поиск для двух сторон с открытой информацией, общий контракт Worker и тесты SDK. |
| `apps/server` | `@chess-2/server` | HTTP/WebSocket, два независимых сервиса комнат/хранилища, серверные проверки и резервное копирование. |
| `docs`, `prompts` | — | Общая архитектура, правила, история проверок и актуальные задания исполнителям. |
| `scripts` | — | Только оркестрация нескольких пакетов и общие проверки структуры/выходов. |

Общий портал `apps/portal`, сервис аккаунтов/друзей `apps/platform` и пакет сессий `packages/session-kit` описаны в [проектном пакете Iva Games](iva-games/README.md), но ещё не реализованы. `games/district` и `games/harbor` содержат концептуальные документы, а не готовые приложения или npm workspaces. Не добавляйте пустые пакеты ради видимости завершённой платформы.

Каждая игра содержит `src`, `public`, `tests` и `scripts`. Тесты, непосредственно расположенные рядом с исходниками, перемещаются с ними. `public` принадлежит игре: модели, шрифты и аудио не складываются в безымянную общую библиотеку. Наличие React/Three.js в обеих играх не требует общего визуального слоя.

## Направление зависимостей

Игры зависят от `@chess-2/engine-sdk`. SDK не знает их фигур, правил, UI, DOM или сетевых комнат. Правила и игровые оценки принадлежат конкретной игре; они не становятся условными ветками внутри универсального поиска.

Сервер импортирует только явные чистые экспорты игровых пакетов: ядра правил и сетевые протоколы/валидаторы. Из `apps/server` нельзя импортировать React-компоненты, сцены, WebAudio и браузерные сохранения. Игры не импортируют серверный SQLite-код. REMORSE не импортирует OVERDRIVE, и наоборот.

SDK и игровые экспорты в этой итерации предназначены для внутренней сборки TypeScript через Vite. Это не заявление о публикации готовой внешней npm-библиотеки. Для внешнего распространения понадобятся отдельные выходы JavaScript, декларации типов, версия и проверка потребителя.

## Сборка и адреса

Все общие команды выполняются из корня, где находятся единственные `package.json` оркестрации и `package-lock.json`. Имя корневого пакета — `iva-games`; внутренние идентификаторы остаются `@chess-2/remorse`, `@chess-2/overdrive`, `@chess-2/engine-sdk` и `@chess-2/server`. У каждого workspace также есть собственный манифест зависимости и команды его задачи.

| Команда из корня | Выход / действие |
|---|---|
| `npm ci` | Установка закреплённых зависимостей и связывание внутренних workspaces. |
| `npm run build:remorse` | `games/chess/remorse/dist`; клиент REMORSE может обслуживаться отдельно от корня своего хоста. |
| `npm run build:overdrive` | `games/chess/overdrive/dist`; самостоятельный клиент Форсажа. |
| `npm run build:client` | Сборка обоих клиентов и сборка общего `dist`. |
| `npm run build:server` | `dist-server/main.js`. |
| `npm run build` | TypeScript, оба клиента, композиция и сервер. |
| `npm start` | Запуск общего Node-сервера из корня проекта. |
| `npm run check` | Границы пакетов, TypeScript, ESLint, весь модульный набор. |
| `npm run workspace:smoke` | Реальный HTTP для общего и двух отдельных выходов, загрузка ресурсов и Worker, запуск пакета сервера. |
| `npm run remorse:test`, `npm run overdrive:test`, `npm run sdk:test`, `npm run server:test` | Целевая проверка конкретного пакета. |
| `npm run test:e2e`, `npm run overdrive:e2e` | Разделённые браузерные наборы игр. |
| `npm run auditions:build`, `npm run auditions:test` | Существующая отдельная сцена сравнения звуков REMORSE. |

`scripts/compose-client.mjs` собирает совмещённый клиент: REMORSE по `/`, OVERDRIVE по `/overdrive/`. Каждая игра собирается с абсолютной базой `/`; её созданные JS/CSS и собственные статические ресурсы доступны по прежним `/assets/...`. Композиция не должна затирать файлы другой игры при совпадении имени с разными байтами. Иконки `remorse.svg` и `overdrive.svg` также сохраняют адреса.

Раздельная сборка не равна публикации. Если отдельно обслуживать `games/chess/overdrive/dist`, хостинг должен возвращать его `index.html` по корню и корректно отдавать все ресурсы. Для сетевой партии нужен Node-сервер с соответствующим статическим выходом и разрешённым origin. Режимы сервера, Docker и backup описаны в [apps/server/README.md](../apps/server/README.md).

Общий запуск по-прежнему использует `dist-server/main.js`, корневой `dist` и прежние переменные окружения. `npm start` следует выполнять из корня. Workspace-команда сервера также нормализует рабочий каталог к корню репозитория, чтобы относительные `DATABASE_PATH`, `OVERDRIVE_DATABASE_PATH` и `STATIC_DIR` не перенаправлялись в `apps/server`. Общий рекомендуемый запуск остаётся корневым `npm start`.

## Что сохраняет механический перенос

Перенос не является новой редакцией правил, движка или оформления. Сохраняются:

- Форматы сохранений, localStorage/IndexedDB-ключи и транзакции рейтинга REMORSE.
- Версии правил, поисковых профилей и сетевых протоколов.
- `remorse_guest` и `overdrive_guest`, отдельные базы и идентификаторы SQLite.
- HTTP/WS-пути, порядок действий, случайные исходы и восстановление комнаты.
- Паузы чтения, отмена Worker, календарь анимации и звука, reduced motion.
- Байты установленных моделей, шрифтов и аудио; у каждой игры остаётся своя художественная система.

Новая структура не даёт разрешение перезагрузить работающую Mac-сборку, удалить данные, занять её порт или открыть видимые тестовые окна. Приёмка проводится в отдельной рабочей копии и на отдельном порту.

Эта карта позволяет читать исторические отчёты без изменения их доказательств. Старый отчёт со старым путём, числом тестов или хешем сборки не становится отчётом новой ревизии после одного переименования пути в тексте.

## Подтверждённое переименование GitHub и локальный origin

Текущий репозиторий — **https://github.com/decorum-guy/iva-games**, его ID — **1469444922**. GitHub поддерживает перенаправления прежнего адреса; создавать новый репозиторий или вручную копировать историю не нужно. Проверьте идентичность репозитория и `git remote get-url origin`. Если локальная копия всё ещё использует прежнее имя, обновите origin с сохранением способа аутентификации. Для HTTPS-клона:

```sh
git remote set-url origin https://github.com/decorum-guy/iva-games.git
git remote -v
git fetch origin
```

Переименование уже подтверждено; дополнительное решение владельца для исправления старого local origin не требуется. Если рабочая копия использует SSH, используйте `git@github.com:decorum-guy/iva-games.git`. GitHub-переименование не переименовывает папку `~/Developer/remorse-chess` на Mac; перемещать рабочую папку работающего процесса для этого не требуется.

Актуальные README-ссылки и задания используют `iva-games`; отдельно проверьте настройки внешних интеграций при их следующем запуске. Не создавайте новый репозиторий со старым именем: это прекращает перенаправление. Исторические GitHub-ссылки на коммиты не являются поводом переписывать старые отчёты. [Официальная инструкция GitHub](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository).
