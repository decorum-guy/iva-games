# Chess 2 — проверка переноса в npm workspaces

25 ноября 2026 года. Исходная ревизия — `b71fad3ee6579c09d6a2f4df8e5628e243e10971`, ветка поставки — `feat/overdrive-sdk`, draft PR №3. Этот отчёт относится к исходникам миграции в том же коммите, в котором добавлен документ. Ревизия документа и изменений доступна через `git log -1 -- docs/VALIDATION_MONOREPO.md`; ниже также указаны точные хеши построенных runtime-файлов.

**Перенос выполнен и проверен на уровне исходников, установки, сборки, модульных тестов и настоящего HTTP/WebSocket. Браузерная визуальная и слуховая приёмка остаётся отдельным незакрытым этапом.** Репозиторий GitHub ещё не переименован; это действие владелец выполняет после переноса. В `main` изменения не объединены, рабочая REMORSE на Mac не активировалась, DNS и публичное размещение не менялись.

## Структура

| Workspace | Ответственность |
|---|---|
| `@chess-2/remorse` · `games/remorse` | Правила, оценка и адаптер ИИ, интерфейс, обучение, сцены, ресурсы, auditions, тесты и профильные скрипты REMORSE. |
| `@chess-2/overdrive` · `games/overdrive` | Самостоятельная игра Форсаж с собственными исходниками, моделями, звуками, тестами и генераторами. |
| `@chess-2/engine-sdk` · `packages/engine-sdk` | Поиск и общий Worker-контракт без зависимости от игр. |
| `@chess-2/server` · `apps/server` | HTTP/WebSocket, независимые комнаты и базы, серверные интеграционные тесты и backup. |

Перенесён 291 существующий файл. У каждого пакета свой манифест, TypeScript- и Vitest-конфигурация. Один корневой lockfile сохраняет исходные версии зависимостей. Пакеты игр экспортируют для сервера только чистое ядро и протокол; корневой UI-barrel не создан. SDK является приватным TypeScript-workspace, компилируемым Vite в потребителей, а не опубликованным npm-пакетом.

Игры собираются независимо в `games/<game>/dist`. `scripts/compose-client.mjs` проверяет конфликты имён по содержимому и формирует общий `dist`: REMORSE `/`, OVERDRIVE `/overdrive/`. База ресурсов — `/`, поэтому перенесённый HTML продолжает разрешать JS, CSS, Worker, модели, шрифты и звук. Лицензионные файлы разделены по игре.

Серверная сборка остаётся `dist-server/main.js`. Внутренние правила включены в bundle; сервер не требует исходных `.ts` в runtime. Workspace launcher устанавливает корневой рабочий каталог, сохраняя прежний смысл относительных путей баз и статики. Для самостоятельной сборки Форсажа добавлен узкий HTML fallback, сохраняющий `/overdrive/` в приглашениях; отсутствующие ресурсы возвращают 404.

## Фактически выполненные проверки

Среда: Linux, Node.js **24.22.3**, npm **11.19.1**. Финальная последовательность выполнилась целиком с кодом возврата 0:

```sh
npm ci --no-audit --no-fund
npm run check
npm run build
npm run overdrive:smoke
npm run workspace:smoke
npm run auditions:build
```

| Выход | Файлов проверено через HTTP | Способ запуска |

Проверены правильное содержимое HTML по `/` и `/overdrive/`, все реально выданные JS/CSS/ресурсы, MIME, ссылки из CSS и входного модуля на Worker, отсутствие ресурсов другой игры в самостоятельном выходе, 404, обе API health-точки и фактическое появление отдельных SQLite-файлов по корневым относительным путям. Готовность устанавливалась по stdout собственного дочернего процесса, не по случайно работающему серверу. Порты выделяла ОС; все дочерние процессы после проверки остановлены.

## Сохранность игрового поведения

- Все **80 исходных публичных файлов** обеих игр побайтно совпали с базовой ревизией: модели, текстуры, звук, шрифты, иконки, манифесты и лицензии.
- Все **148 исходных файлов `src`** совпали после нормализации только статических путей `import`/`export`. Изменений правил, оценки, сцен, длительностей, сохранений и выбранного аудио в них нет.
- Отдельно все 19 файлов обоих ядер и SDK совпали побайтно без нормализации.
- Оба построенных Worker сохранили хеши предыдущей сборки.
- Ключи IndexedDB/localStorage, версии правил и протоколов, cookie, SQLite `application_id` и схемы не менялись. Это проверка кода; личные данные владельца на Mac здесь не читались и не мигрировали.

Независимое чтение переноса другим агентом подтвердило ту же сохранность исходников и ресурсов. Замечания к вложенным Docker ignore-путям и неоднозначному `cwd` сетевого E2E-фикстурного сервера исправлены. Исправлена передача аргументов в корневых npm-командах; `--list` теперь доходит до Playwright и не поглощается вложенным npm.

## Незакрытые проверки

В текущей восстановленной среде Chromium и WebKit для Playwright не установлены. Попытка запуска остановилась на `browserType.launch: Executable doesn't exist`; приложение в браузере не исполнялось. После исправления передачи аргументов успешно выполнено обнаружение:

- REMORSE — **150 сценариев в 10 файлах**.
- OVERDRIVE — **27 сценариев в одном файле**, три конфигурации устройств.
- Auditions — **12 сценариев в двух файлах**.

Эти числа — **обнаруженные, не пройденные браузерные тесты**. WebGL, реальный браузерный Worker/AudioContext, полноценный UI-проход уроков и двух игроков, непрерывные анимации, слышимый микс, FPS и физический телефон остаются локальной приёмкой. Dockerfile и контекст обновлены; Docker-образ в этой итерации не собирался. Публичная работа с разных сетей также не проверялась.

Локальные подробные отчёты находятся в игнорируемой `.qa`: `overdrive/production-2835c69b/report.json`, `workspace-migration-f8cfb5d9/report.json`, `monorepo-source-audit.json` и `monorepo-build-hashes.json`. Они не включаются в Git или GitHub Actions artifacts.
