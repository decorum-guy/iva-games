# Добавить новость в «Район»

Работай в отдельной ветке от актуального игрового кандидата. Прочитай описание владельца и [правила новостей](../games/district/NEWS_SYSTEM_V1.md). Определи, какое решение появится у игрока, для какой географии, когда раскрывается зона и в какой момент меняется состояние партии.

1. Подбери типизированные эффекты из [каталога](../games/district/src/territorial/news-catalog.ts). Для нового семейства назначь уникальный `templateId`, класс, стадию, допустимую цель, срок и параметры. Дополнительная редакция заголовка сохраняет прежний идентификатор и вес семьи. Для нового оператора сначала реализуй его в общем ядре и проверь реальные последствия, доступность цели, срок, дефицит банка и стык с другими эффектами.
2. Напиши заголовки RU/EN для каждой стадии и короткий текст состоявшегося эффекта. До применения выдавай только заголовок, раскрытую зону и объявленный срок. Проверяй JSON обоих клиентов и бота. В раннем прогнозе никто не должен узнать скрытый сектор, исход, будущие постройки, игроков или ожидаемый ущерб. На карте покажи зону целиком. Реальный результат с персональными изменениями публикуется из уже применённой транзакции.
3. Подними версию изменённого каталога либо профиля. На старых снимках прогони появление новости, повтор команды и восстановление матча из SQLite. Снимок содержит исходные шаблоны и параметры. Для восстановления публичной истории используй сохранённые сообщения.
4. Подай новый набор в `validateNewsCatalog`, профили — в `validateNewsProfile`. В отдельной fixture проведи предложение, применение, каждый исход и истечение через тот же движок, что обслуживает матчи. Убедись, что у каждой обычной карты есть допустимые цели, выплата неделимого остатка справедлива, а повтор команды не выдаёт награду дважды. Для нового редакционного варианта проверь неизменность количества семейств.
5. Открой локальное игровое превью на двух независимых местах. Проверь обе локали, прогноз, отмену, уже наступившее воздействие, мобильную карту и восстановление. Проведи сопоставимые партии до результата и запиши измерения, если изменил частоту или экономику. Приложи версии данных, команды проверок и результаты к обычному PR. Учебные и принудительные сценарии доступны только локальным fixtures.

## Проверка расширения данными

Из корня worktree запусти пример на Node с поддержкой TypeScript. Он добавляет помощь от найденного склада только во временную копию каталога. Проверяется принятие нового описания и отказ при повторном ID или неизвестном операторе. Игровое действие дополнительного шаблона отдельно проверь в изолированной fixture движка.

```sh
node --experimental-strip-types --input-type=module <<'JS'
import assert from 'node:assert/strict';
import { newsCatalog, validateNewsCatalog } from './games/district/src/territorial/news-catalog.ts';
const supplies = structuredClone(newsCatalog.find(card => card.templateId === 'G02'));
supplies.templateId = 'G11';
supplies.headlines.applied = { ru: 'В порту открыли старый склад', en: 'An old port warehouse reopens' };
supplies.description = { ru: 'Банк распределил по одной шерсти на владельца.', en: 'The bank allocated one wool per owner.' };
supplies.effects = [{ op: 'grant', basis: 'owner', resources: { wool: 1 }, cap: 1 }];
validateNewsCatalog([...newsCatalog, supplies]);
assert.equal(newsCatalog.length, 25);
assert.throws(() => validateNewsCatalog([...newsCatalog, supplies, supplies]));
assert.throws(() => validateNewsCatalog([{ ...supplies, effects: [{ op: 'script' }] }]));
JS
```
