# Довести обучение REMORSE на Mac

## Задание

Владелец повторно отклонил обучение после поставки `16ef93e0ef2eb1f04dbc01199fed273d6b8a97b6`. Оно проводило через координаты, но не объясняло причинную связь: взятие → число на кубике → эмоция фигуры → ограничения → проверка правила. Приближение происходило после упражнения. Тесты предыдущей поставки не являются приёмкой понятности.

В свежем `main` уже есть исправление контроллера, новые обязательные объяснения RU/EN, синхронизация фокуса и проверки. Твоя задача — **получить этот код, проверить обновлённую игру на Mac, исправить все обнаруженные проблемы и оставить готовый локальный запуск**. Не заканчивай одним планом или отчётом о том, что сборка прошла. Владелец делегировал обычные решения, не задавай ему промежуточных вопросов.

Основной исполнитель — выбранная владельцем **Sol 6.2 / max**. Для визуального приёмщика используй реально доступную **6.1 Terra / high**, при поддержке API — `gpt-6.1-terra` с `high`. Проверь доступный способ запуска; не выдумывай флаги и не называй другую модель Terra. Приёмщик должен действительно видеть обновлённый браузер и играть в нём. Если конкретный доступ не работает, выполни остальную доступную работу и явно укажи невыполненную часть; не подменяй её заявлением об успешной приёмке.

## Подготовка

1. Проверь `git status`, текущую ветку, remotes и уже работающие preview. Получи свежий `origin/main`; сохрани незакоммиченные изменения. При необходимости используй отдельный worktree. Не делай destructive reset и не очищай сохранения пользователя.
2. Прочитай `AGENTS.md`, `docs/BUILD_STATUS.md`, `docs/TUTORIAL_CLARITY_REVIEW.md`, этот документ целиком, `docs/TUTORIAL.md`, `docs/RULES_DIGITAL_V1.md`, `docs/reference/transcript.md` и руководство дизайна из проекта. Не повторяй предыдущий `FINISH_PLAYABILITY.md` вместо текущей задачи.
3. Проверь новый код на отдельном порту, например `4175`, до замены пользовательского `4173`. Сначала сверяй фактический build/commit: открытая вкладка может показывать старый `dist`.
4. Для нового прохождения используй отдельный тестовый профиль/контекст браузера или штатный перезапуск только обучения. Старое сохранение без нового поля продолжится со старого места и не покажет пропущенные ранее пояснения. Не обнуляй IndexedDB, Elo или обычные партии владельца.

## Уже подготовлено — сохранить и проверить

- `Step.after` / `TeachingBeat`, `pendingTeaching`, `teachingBeat()` и подтверждение без изменения game state.
- 29 обязательных кратких пояснений к 27 действиям, сохранены все прежние 55 ID и позиции. Текст содержит причину и правило; необязательная справка не должна хранить единственное объяснение основного механизма.
- Соперник не ходит и упражнение не начинается, пока результат не подтверждён.
- Фокус и новое состояние появляются вместе на остановке кубика. Нет исторического поиска эффекта в конце позиции. Акцент материала остаётся заметным после прибытия камеры.
- Возврат камеры закрывает ввод и запуск следующего скрипта до окончания перехода, включая новую подготовленную позицию. Reduced motion не задерживает статичный показ.
- Правильная попытка запрещённого хода подтверждает правило без красной ошибки и без повторного проигрывания прежнего действия.
- Последний результат открывает следующий пример одним подтверждением, если между ними был только пустой экран завершения.
- Три обязательных пояснения выделяют HUD взятий/материала. Рейтинг, правила, модели, записанные звуки и плавный переворот из последней Mac-поставки сохраняются.

## Приёмка понятности — главный критерий

Первый проход приёмщика проведи **по экрану**, не подсказывая ему координаты, будущие результаты и содержимое `lessons.ts`. Дай цель: пройти обучение как новичок. Исходники и тестовые фикстуры можно читать после этого прохода для диагностики.

На каждом впервые показанном механизме приёмщик должен суметь ответить по обязательному интерфейсу:

1. Что сейчас произошло и какая фигура изменилась?
2. Если был кубик — какое число выпало и что оно означает?
3. Почему возникло состояние и что теперь можно/нельзя делать?
4. Куда смотреть: на фигуру, её счётчик, строку взятий или панель?
5. Какое следующее действие требуется от игрока?

Если ответ требует догадки, дополнительной справки или знания тестового сценария, это дефект. Исправь, затем повтори соответствующий момент. Не превращай эти вопросы в новый экзамен или дополнительные окна для владельца: это критерии разработческой проверки.

### Обязательные контрольные моменты

- **Первое взятие.** Видны выпавшая 4 и «Без изменений», простое объяснение реакции пешки и памяти реакции. Затем обязательная компактная таблица: 1 — опустошение, 2–3 — вина, 4–5 — без изменений, 6 — ярость. Понятно, что остальные реакции будут испытаны дальше. Не переносить ошибочный пример «4 — вина» из отзыва в правила.
- **Вина.** После `c3 → c4` и двойки ладья выделяется и приближается одновременно с новым эффектом. Объясняется, что она сожалеет о взятии, может ходить, не может брать и шаховать, продолжает блокировать линию. Даже если игрок ничего не нажимает несколько секунд, соперник не отвечает. После подтверждения возвращается общий план; затем проверяются запрет взятия и разрешённый обычный ход. В конце не возникает нового запоздалого приближения.
- **Опустошение.** После единицы сначала объясняются причина, неподвижность и риск исчезновения; затем показан счётчик. Три полных цикла и один ход каждой стороны за цикл понятны без «Почему так». Счётчик можно читать до подтверждения. Милосердие и исчезновение объясняются как разные события.
- **Слон.** Видно начало лечения и реальное исцеление. Соседство включает диагонали и должно быть непрерывным; полный цикл не путается с одним перемещением. Объясняется, что исцеление не стирает запомненную реакцию. Сам слон не берёт и не шахует; взятие слона и исключения показаны ясно.
- **Стыд.** При каждом фактическом переходе показывается именно изменившаяся фигура: вина → опустошение → смена армии. Есть причина, длительность, защита своим слоном, отсутствие ускорения от второго слона и иммунитет ярости. Новая реакция после обращения понятна.
- **Король.** Немедленное снятие вины/опустошения отличается от ожидания слона. Не исчезают ограничения безопасности короля и исключение ярости.
- **Конь и ярость.** Первое обычное взятие без кубика, второе с 6. Второе действие принадлежит той же фигуре, всего действий не больше двух. Жажда крови возникает у берсерка при трёх взятиях всего, включая предыдущее первое. Второе действие не тикает счётчики отдельно. Своя взятая фигура не превращается во вражеский трофей.
- **Превращение.** Выбор Q/R/N сохраняет состояние/реакцию/число взятий. Слон объясняет очищение даже после показанной 6 и отсутствие бонуса.
- **Финал.** Оба пути работают: продолжить текущую позицию с ИИ и открыть создание новой партии. Нет лишних пустых экранов там, где уже был подтверждён результат.

Проверяй реальную поверхность фигуры и материал её армии, а не только наличие `data-focus-square`, рамки или текста в DOM. Заголовки, фон, эффект и масштаб должны направлять взгляд. Не добавляй новые большие панели, постоянное мерцание и длинные трактаты. Не возвращай пояснения о заранее определённых учебных бросках.

## Проверки состояния и компоновки

- Пройди все девять уроков RU/EN и обе развязки. Проверь старое сохранение на границе 3→4.
- Перезагрузи страницу на удержанном результате, смени язык, открой/закрой справку и выйди в меню. Продолжается тот же результат, без повторных кубиков, звуков, команд, тиков и рейтинга.
- Проверь выход/перезапуск во время броска и возврата камеры; запоздалый скрипт не действует в новой позиции.
- Проверь 3D и 2D, обычное и уменьшенное движение. В 2D смысл каждого объяснения сохраняется.
- Размеры: 1440×900, 1280×800, фактический ноутбучный viewport, 390×844, 360×800, 844×390, 568×320. Основной текст, правило и кнопка доступны без прокрутки страницы или обязательной прокрутки панели. На коротком landscape исправь компоновку/сократи повторения; не прячь правило и не уменьши шрифт до нечитаемости.
- Полная таблица граней, длинное пояснение жажды крови и обе финальные кнопки должны помещаться. Убедись, что новая высота панели не делает доску неудобной для касаний.
- Сохранённый mute остаётся mute. Не переделывай записанные звуки или плавный переворот без конкретного нового дефекта.

## Команды и доказательства

```sh
npm ci
npm run check
npm run build
REMORSE_TEST_PORT=4175 npm run test:e2e
```

Запускай тесты против **новой** сборки. Не переиспользуй старый сервер на `4175`, если он обслуживает старые файлы. Если нужные Playwright-браузеры отсутствуют, установи их штатным способом. Окружение подготовки подтвердило 213 unit tests и сборку; 82 browser tests только собраны, их выполнение на новой ревизии не заявлено.

Файлы `tests/e2e/teaching.spec.ts`, `tutorial.spec.ts` и `playability.spec.ts` теперь проверяют удержанные результаты и переходы. Исправляй конкретные провалы, не ослабляй проверки и не подменяй визуальную оценку DOM-атрибутами. Математическая проверка камеры не подтверждает качество кадра.

Сохраняй небольшое число полезных скриншотов/коротких записей и traces локально в игнорируемой `.qa/`. Не загружай их в Git или GitHub Actions artifacts. Для отчёта укажи точную ревизию, build, модель приёмщика, браузер, viewport, что реально увидел, что исправил и что не проверял. Не выдавай эмуляцию за физический iPhone.
