## Территориальный «Район» v0.4

1. Получи актуальные refs и опиши, какой выбор даст эта география. Определи острова, производящие земли, удобные старты, специализации портов, пути по воде и доступность каждого ресурса. Прочитай правила текущей версии и раздел о географии новостей. [Правила v0.4](../games/district/RULES_V0_4.md) · [Новости](../games/district/NEWS_SYSTEM_V1.md)
2. Создай данные `games/district/maps/territorial/<id>.<version>.json` со схемой 3, профилем `district@0.4`, именем RU/EN, `supportedPlayers` и числом участков суши `landmasses`. Для изменения существующей географии выпусти следующий номер. Каталог подхватывает файлы из этой директории. [Исходник Лазурной бухты](../games/district/maps/territorial/azure-bay.2.json)
3. В каждом секторе укажи стабильный ID, оба названия и земли формата `[q,r,resource,number,tags]`. Ресурсы — `wood`, `brick`, `grain`, `wool`, `ore`. Пара `null,null` обозначает непроизводящую сушу. Вода занимает пространство между островами. Граница сектора строится по открытым сторонам его гексов и должна замыкаться в один контур без дыр. Точки и стороны на стыке получают сектор, описанный первым в файле. Координаты графа вычисляются на целой решётке. В каждой точке сохраняется одно назначение `eventSectorId`.
4. Укажи `floodplain` для пойменных земель. Лесная местность автоматически даёт узлам `woodland`. Метку `woodland` также можно присвоить явно. Одиночная сторона гекса даёт двум вершинам `coastal`. Граф фиксирует метки до отрисовки. Для каждой переправы укажи свои `a`, `b` и `eventSectorId`. Ссылка на точку — `[q,r,corner]`, угол 0 сверху, углы 1–5 по часовой стрелке. Порт ссылается на береговую точку через `at`; `resource:null` обозначает общий порт.
5. Запусти `npx vitest run --project district games/district/tests/territorial-maps.test.ts` и `npm run build:foundation`. Валидатор проверяет реальные берега и пересечения, достижимость по суше и морю, количество островов, географию угроз, границы секторов и восемь разнесённых производящих стартов. В тесте четвёртая география создаётся отдельными данными. [Валидатор](../games/district/src/territorial/maps.ts) · [Проверка четвёртой карты](../games/district/tests/territorial-maps.test.ts)
6. Проведи сравнимые партии нового ядра на 2, 3 и 4 места со всеми четырьмя пресетами новостей. Проверь достижение цели, доступность ресурсов, портов и морских путей, работу погодных событий в подходящих секторах. В локальном браузере проверь начальный и застроенный стол, касания, объявленную зону прогноза и возврат в сохранение. Передай измерения, скриншоты локального превью и обычный PR.

## Карты опубликованных матчей v0.2/v0.3

В `decorum-guy/iva-games` получи актуальные refs. Прочитай [инструкции проекта](../AGENTS.md), [формат карт](../games/district/MAPS.md), [правила островов](../games/district/RULES_V0_3.md) и [арт-направление](../games/district/MAP_ART_DIRECTION.md).

1. Опиши силуэт, размещение общественных мест и задуманный выбор для игроков. Создай один файл `games/district/maps/<id>.<version>.json` со схемой 2, RU/EN и пятью связными зонами. Оставь опубликованные версии на месте и проверь предыдущие снимки.
2. Запусти `npm run district:maps -- --base <base-ref>`, `npm run district:test` и `npm run build:foundation`. Проверь автоматическое появление превью и новой карты при создании комнаты.
3. Проверь старт, закрепление снимка, возврат и партии на 2–4 места. Используй `npm run district:simulate -- --islands` для сравнимых прогонов. Покажи пустой и заполненный вид и запиши измеренные изменения по соседству, доходу и целям.
4. Опубликуй карту и отчёт отдельным коммитом без force-push. Если пожелание требует новых правил, зафиксируй его для отдельной версии. Публикация игрового сервера проводится отдельно.

Результат — карта, ревизия, ссылка на демонстрацию, измерения и границы проверки.
