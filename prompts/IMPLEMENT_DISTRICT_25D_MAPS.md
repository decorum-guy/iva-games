# Локальный исполнитель — красивые карты «Района» в 2.5D

Ты — **GPT‑6.2 Sol**, основной локальный исполнитель Iva Games на Mac. Владелец разрешил переделку карты «Района» и поручил тебе довести её до работающего красивого результата. Выполни задание целиком, с настоящей игрой, проверками и отдельной демонстрацией. Основной веб-чат подготовил эту постановку; он не заявляет, что новые карты уже реализованы.

## 1. Главное требование владельца

Технический прототип работает, но его квадратная карта слишком простая. Нужна выразительная **2.5D-карта уровня визуального ориентира Colonist**: цельная география, вода, берег, острова, маленькие объёмно нарисованные здания и понятные действия. Собственная городская стилистика «Района». **Полноценный Blender, 3D-моделирование и свободная камера в этот этап не входят.**

Сделай минимум три карты: один нерегулярный массив суши с бухтой, два берега и четыре острова. Они отличаются формой и реальным соседством. Добавление следующей совместимой карты по описанию владельца должно сводиться к данным, проверке и публикации. Архитектура должна поддерживать десятки таких карт без отдельных экранов и ветвлений для каждого `mapId`.

Обязательная подробная постановка — [MAP_ART_DIRECTION](../games/district/MAP_ART_DIRECTION.md). Прочитай её целиком и реализуй её контракт. Она задаёт художественные признаки, три географии, новый профиль соседства/событий, совместимость и критерии приёмки. Не ограничивай работу косметической заменой квадратов на гексы.

## 2. Модели и распределение ответственности

Ты, **Sol**, принимаешь архитектурные решения, ведёшь интеграцию и проверяешь весь результат. Для сложной, но ограниченной реализации привлекай настоящего субагента **GPT‑6.2 Astra с `reasoning_effort=low`**, минимальной поддерживаемой настройкой. Это просьба о настройке реального запуска, а не текстовое заявление «Astra сделала» и не обещание полного отсутствия рассуждений.

Подходящие задания Astra: единый набор SVG-зданий по заданным размерам; отрисовка берега по готовой геометрии; конкретный компонент карты; подсказки и инспектор по готовому API; исправление воспроизведённого дефекта. Передавай точные входы/выходы, список разрешённых файлов, состояния, ограничения и проверку. Общее решение о версиях, соседстве и правилах остаётся у тебя. Проверяй и интегрируй результат, не отдавай неопределённое «придумай всё заново».

Проверь доступность указанных моделей и effort в своей среде. Если запуск Astra недоступен, назови ограничение, не имитируй делегирование и продолжай доступную работу Sol. В отчёте укажи фактически запущенные конфигурации. Результат Gemini ещё ожидается; это задание не запускает Gemini и не заменяет его предложения своими догадками.

## 5. Порядок реализации и публикации

### Этап A — география, версии и сохранения

Изучи жёсткие предположения в `games/district/src/map-schema.ts`, `core.ts`, `types.ts`, `bot.ts`, `runtime.ts`, `apps/platform/src/service.ts` и `apps/portal/src/District*.tsx`.

Введи новый профиль/schema для гексов и островов. Отдели стабильные клеточные ID и экономическое соседство от координат отрисовки. Нормализуй данные карты в авторитетный граф; используй его в ядре, ботах, доходе, целях, парках и UI. Вода не продаётся, соседи через неё не возникают. Глобальные торги/обмен сохраняются, транспортную систему не добавляй.

Опиши в новой редакции правил точное соседство и пять зон события «Перекопанная улица» из постановки. Сохрани прежние цены/сроки/число раундов как контроль. Поддержи старые v0.2 матчи и не начатые лобби через явную версию/адаптер, включая платформенную нормализацию карты, добавление и версию бота, старт по записанным версиям комнаты. Простая замена констант, после которой старые партии становятся несовместимыми, не принимается. Старые JSON не переписывай.

Проверь новую геометрию и старые сохранения целевыми тестами. Опубликуй законченный этап отдельным коммитом без force-push.

### Этап B — одна законченная карта в настоящей игре

Доведи «Лазурную бухту» до цельной сцены: вода, мелководье, берег, суша, участки, площадь, нейтральные дома, все здания двух уровней, парк до/после стройки, владение. Рендер подключён к серверному состоянию и реальным командам. Цены/эффекты вычисляются правилами.

### Этап C — три географии и простое авторство

## 6. Проверки, которые определяют готовность

**Совместимость и сеть:** старый матч v0.2 и старое лобби; прежняя парковая проба; новая партия на каждом островном профиле; два независимых клиента; утрата ответа и та же команда без двойного эффекта; рестарт; приватность; одинаковый итог. Не показывать невидимые противнику данные в DOM или JSON. Сохранить запрет подтверждать несохранённую ставку и защиту таймера от старого ответа.

**Геометрия:** число массивов суши; уникальные IDs; валидные симметричные рёбра; видимые границы совпадают с соседством; вода/декор не перехватывают выбор; нет пересечений hit areas; зоны события корректны; все цели имеют необходимые геометрические возможности. Пустые места между островами не считаются игровой клеткой.

**Боты и экономика:** адаптируй политику ко всем новым картам без доступа к секретам. Повтори базовую матрицу 108 матчей: 3 карты × 3 состава (2/3/4) × 3 группы политик × 4 seed. Опиши распределённые/дополнительные ротации и фактическое число запусков; полная ротация всех случаев — 324. Дай раздельные результаты по картам. Посмотри доход/степени соседства, здания, парки, цели и незавершённые игры. Изменение географии не объявляй сбалансированным из-за отсутствия исключений; конкретные перекосы разбери и запиши. Не менять весь баланс одновременно с оформлением без измеренного основания.

**Внешний вид:** три превью; пустая/застроенная/финальная карта; все здания двух уровней и оба состояния парка; выбор и цена; входящий договор; активная ставка; hover/focus/tap. Проверь desktop RU/EN, узкий Chromium/WebKit и физический телефон при доступности. Карта, действие и таймер не конфликтуют; масштабирование/панорама не вызывают ход; фокус и reduced motion работают. Зафиксируй фактическую производительность на доступном устройстве без выдуманного FPS.

Используй существующие команды как исходную регрессию, адаптируя сценарии для нового профиля, а не удаляя legacy-проверки:

```sh
npm ci
npm run district:maps
npm run district:test
npm run lint:platform
npm run build:foundation
npm run portal:e2e -- --workers=1
npm run district:browser -- --acceptance
npm run district:simulate
npm run district:simulate -- --park-probe
npm run check
```

Общий check выполняй на финальном согласованном кандидате; повторяй широкий прогон только после изменений, которые этого требуют. При изменении общего выпуска проверь затронутые сборки/образ. На Mac расширенный браузерный сценарий использует Chromium и WebKit. Не выдавай эмуляцию за физический iPhone.
