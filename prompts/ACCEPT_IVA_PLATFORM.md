# Локальная приёмка платформы Iva Games

## Задача и границы

Принять реальный интерфейс и интеграцию общего фундамента, сохранив опубликованную шахматную приёмку `c18e57c` и отдельные действующие демосерверы. Сначала читать корневой AGENTS.md, [текущий статус](../docs/iva-games/BUILD_STATUS.md), [README сервера](../apps/platform/README.md) и [фактический API](../apps/platform/API_CONTRACT.md).

Получить актуальную `feat/iva-platform-foundation` / PR №5: она уже включает шахматный перенос и PR №6. Не повторять создание платформы, перенос шахмат или пройденную локальным агентом приёмку игр. Сверить актуальные remote refs и сохранить новые изменения. Ни отчёт Mac по шахматам, ни исторический браузерный отчёт Remorse не подтверждают интерфейс нового портала.

## Запуск и изоляция

Использовать отдельный рабочий checkout/ветку, свободные порты и отдельные временные базы. Не останавливать действующие шахматные процессы на 4173 и 4185. `npm ci`, затем `npm run check:platform`, `npm run build:foundation` и `npm run platform:smoke`. Последняя команда самостоятельно запускает изолированный собранный сервер, проходит двух клиентов/бота и рестарт, удаляет временные базы/почту и не использует браузер. Изучить [.env.platform.example](../.env.platform.example); секреты хранить только в игнорируемом окружении.

Для development: `npm run dev:platform` и во втором терминале `npm run dev:portal`; сайт `http://127.0.0.1:5175`. Файловый локальный mail sink не отправляет писем; ссылки доступны в `.runtime/platform-mail`. Это режим проверки, а не production-почта. Никакие тестовые учётные записи не создавать в базе пользователя.

Выполнить `npm run check:kz-bot`, сверить [источник доступа](../docs/iva-games/INFRASTRUCTURE_ACCESS.md). Проверять существующий SSH alias с известным host key; не менять сервер, ключи или прокси и не создавать новый туннель без необходимости и имеющейся авторизации. Отдельно фиксировать SSH и реальный proxy route. Облачное отсутствие SSH-конфигурации не переносить на Mac.

## Сценарии в независимых браузерах

1. Два отдельных профиля проходят регистрацию, подтверждение email из локального sink, выход/вход и восстановление. GET почтовой ссылки сам не потребляет токен. После reset старая cookie не позволяет действовать. Неверные данные дают понятные ошибки RU/EN.
2. Поиск handle, заявка, принятие, повтор клика, встречная заявка, отклонение, удаление и block. Чужие email/Telegram не видны. Разблокировка сама не восстанавливает дружбу.
3. Host создаёт «Пробный стол», приглашает друга. Друг принимает приглашение, видит резерв и отдельно входит. Посторонняя учётная запись по пересланной ссылке не получает доступ. Проверить истечение резерва и закрытие комнаты.
4. Добавить ботов, удалить бота, изменить вместимость, передать host. Любое изменение состава сбрасывает готовность людей. Готовность другого человека нельзя установить с аккаунта host. Внутри начатого матча состав зафиксирован.
5. Завершить техническую партию вдвоём и с ботами, в том числе комнату на шесть мест. Во время нераскрытого раунда сетевой ответ второго клиента не содержит выбор первого. Обновить страницу, временно отключить сеть, перезапустить процесс на той же базе — место и уже принятые действия сохраняются.
6. Проверить восстановление после потерянного ответа без повторного действия. Старая revision обновляет состояние через понятную ошибку, не повторяет выбор молча. Завершённая партия остаётся завершённой.
7. Remorse/Overdrive без адаптера помечены недоступными для общих комнат. «Район»/«Гавань» не выдаются за готовые игры. Технический стенд назван соответствующим образом.

## Визуальная приёмка

Проверить desktop и узкий экран телефона, увеличенный текст, клавиатуру, заметный focus, читаемые ошибки и состояния загрузки. Переключить RU/EN на входе, в друзьях, приглашениях, комнате, техническом матче и Telegram-панели. Доступ к выходу/профилю на телефоне обязателен. Контент не должен обрезать действия или перекрываться навигацией.

В текущем cloud проходе доступные браузеры не смогли открыть workspace preview; визуальная приёмка не выполнена. Не представлять сборку, source review или HTTP-тест как её замену. Не обходить ограничения инструмента браузера через скрытые endpoint или альтернативное исполнение. Локальный исполнитель использует доступную разрешённую браузерную среду на своём устройстве.

## Telegram и внешняя почта

Сначала пройти изолированные mock-тесты привязки/очереди. Проверить unavailable без config, явное consent, cancel, mute/unmute, unlink, перезагрузку страницы во время подключения и истечение попытки. Пересланная Start-ссылка без proof-кода и исходной web session не завершает привязку.

Для живой активации нужны выделенный бот, фактический HTTPS origin, webhook secret, ключ шифрования proof, настоящий proxy route через kz-bot и SMTP. Реквизиты нельзя брать у другого проекта по совпадению назначения. Проверка конфигурации не регистрирует webhook автоматически.

Реальную доставку проверять только с явно разрешёнными тестовыми получателями и отдельно от mock-прохода. Зафиксировать три разных факта: Bot API принял sendMessage; человек увидел сообщение; человек открыл правильное актуальное приглашение. Один из них не доказывает остальные. При mute, отзыве приглашения или блокировке новая отправка отменяется. Не проводить рассылку друзьям владельца и не добавлять напоминания.

## Отчёт

Внести в BUILD_STATUS точный проверенный SHA, команды и результаты, реально выполненные браузерные сценарии, нерешённые дефекты и состояние внешней активации. QA видео/скриншоты/трассы, почта и базы остаются локальными и не выгружаются в Git или Actions artifacts. Публичный выпуск и подключение шахмат — самостоятельные проверяемые шаги.
