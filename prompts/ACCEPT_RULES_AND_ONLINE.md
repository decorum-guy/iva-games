# Живая приёмка правил, обучения и сетевых комнат

Ты работаешь на Mac владельца в `~/Developer/remorse-chess`. Прими актуальный `origin/main`: новый сетевой сервер и браузерная интеграция уже реализованы. Не начинай их разработку заново по старому `IMPLEMENT_ONLINE_ROOMS.md`. Прочитай `AGENTS.md`, `docs/BUILD_STATUS.md`, `docs/VALIDATION_RULES_AND_ONLINE.md`, `docs/RULES_AUDIT_2026_11_25.md`, `docs/TUTORIAL_EDITORIAL_AUDIT_2026_11_25.md`, `server/README.md`, `docs/DEPLOYMENT.md`.

Задача — самостоятельно провести оставшуюся живую приёмку, исправить обнаруженные дефекты и только затем активировать принятую сборку на 4173. Пользователя не спрашивать о рутинных решениях. Окна проверок не показывать, фокус не перехватывать, звук на динамики не выводить. Существующие звуки, 3D-постановку и художественное направление не переделывать. Пользовательские партии, Elo, обучение, настройки и mute сохранить.

## Изоляция и запуск

Сначала проверь Git и текущие процессы. При чужих незакоммиченных правках работай в отдельном worktree, ничего не стирай. Сохрани точную ревизию текущей рабочей сборки и необходимые данные для отката. Новую версию до приёмки запускай на отдельном свободном порту, например 4175, с отдельной `.qa/online-acceptance.sqlite` и тестовыми профилями.

```sh
npm ci
npm run check
npm run build
HOST=0.0.0.0 PORT=4175 DATABASE_PATH=.qa/online-acceptance.sqlite npm start
```

`npm start` запускает Node с сайтом, API и WebSocket. `vite preview` сетевой сервер не заменяет. Полный Playwright теперь сам запускает сервер с отдельной тестовой базой, если явно не указан `REMORSE_REUSE_TEST_SERVER=1`. Выбирай отдельный свободный `REMORSE_TEST_PORT`; не используй реальную базу владельца. Браузеры Chromium/WebKit установи штатным способом при необходимости.

## Обучение и текст — личный проход

Привлеки реального отдельного агента **gpt-6.1-terra / high** для компьютерной приёмки. Если такого агента нет в доступных средствах, прямо зафиксируй это, не приписывай ему проверку. Сам также прочитай весь обязательный текст на экране.

Пройди все девять уроков с нуля на RU и EN через интерфейс, оба финальных выхода, восстановление посреди удерживаемой реакции и осмотра. Не инъецируй завершённый прогресс вместо прохода. Посмотри как человек, знакомый с обычными шахматами, но впервые открывший REMORSE:

- Понятны причина состояния, текущая грань и полная таблица кубика? **1 — опустошение, 2–3 — вина, 4–5 — без реакции, 6 — ярость.**
- Сразу понятно, нужно ли читать, выбрать фигуру, сделать ход или подтвердить наблюдение? Кнопка обещает именно следующее действие?
- Камера приближается на появлении эффекта, усиленное свечение и счётчик читаемы, соперник ждёт объяснения?
- Ясно, что слон не берёт и не даёт шах; соседство — восемь клеток; ход сближения не входит в цикл; лечение не стирает память реакции?
- Нет длинного двойного объяснения, лишнего «поздравления», придуманных мотивов или сообщения про фиксированные учебные броски?
- На ноутбуке и телефоне в обеих ориентациях фигура, обязательная инструкция, сроки и кнопка видны вместе. Документ не прокручивается.

Сокращай повторы, но не удаляй существенное правило. Любую новую правку текста проверь в обеих локализациях и на соответствующем шаге.

## Два настоящих сетевых игрока

Используй два независимых браузерных контекста с разными cookies. Они должны играть через сервер, а не через общий IndexedDB. Запусти `tests/e2e/online.spec.ts`, затем лично проверь 3D и обычное движение: новые автоматические сценарии в основном работают в 2D с reduced motion.

Через UI создай комнату, скопируй приглашение, зайди вторым профилем, подтверди готовность обоих. Сыграй полную партию от стандартной позиции с обычными бросками, стараясь принимать осмысленные решения. Не подменяй правила, кубик или доску из клиента; для отдельных редких 3D-сцен допустим изолированный явно помеченный серверный fixture только в QA, не в production API.

Проверь обе стороны, разные языки и ориентации, взятые фигуры и +N, все эффекты, бонус, жажду крови и взятие союзника, лечение/обращение, выбор превращения, шах и мат. Сверь редкие правила с `RULES_DIGITAL_V1.md`, а не с обычными шахматами.

Особое внимание очереди: один клиент с обычным движением, другой с reduced motion. Второй делает допустимый бонусный ход, пока первый ещё показывает бросок. Первый обязан принять обе ревизии, показать сцены по порядку и разрешить новое решение только на актуальной позиции. После reconnect прошлые кубики, звуки и финальные сцены не повторяются.

Проверь перезагрузку, реальный обрыв соединения, возврат телефона, закрытие и повторный запуск Node с той же SQLite посреди бонуса. Состояние, место, история и уже выпавшая грань сохраняются. Старое соединение после открытия места другой вкладкой не командует. Отключение не присуждает поражение; свою сдачу можно отправить при отсутствующем сопернике.

Ничья требует другого игрока; старое предложение после хода не принимается. Реванш требует обоих, создаёт новую игру, меняет цвета, не меняет прошлый результат. История только просматривается; undo и локальный Elo к сетевой партии не применяются. Ошибки входа и занятого места должны быть понятны без технических кодов.

## Активация и отчёт

После исправлений повтори только затронутые проверки плюс необходимые общие ворота. Сохрани краткий фактический отчёт с ревизией, hash загруженного JS, прошедшими и непрошедшими сценариями. Фото/видео/трассы — только локально в `.qa`, не в GitHub и не в Actions artifacts. Не складывай частные партии и cookies в Git.

Затем переведи 4173 на `npm start`, сохранив origin и браузерные данные владельца; постоянную SQLite положи в `data/remorse.sqlite`, а не в тестовую базу. Перезагрузку актуального пользовательского экрана делай после сохранения и проверь восстановление. На Mac и LAN должны работать и страница, и новая комната.

Публикация на **remorse.chess-2.online** — следующий этап с проверкой доступного сервера и DNS. Корневой **chess-2.online** не переделывать: каталог и дизайн Claude запланированы после второй игры. Не объявляй публичный сайт запущенным по одному локальному успешному тесту.
