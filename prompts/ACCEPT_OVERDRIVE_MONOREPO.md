## 3. Сборка и регрессии пакетов

Из корня отдельного worktree:

```sh
npm ci
npm run check
npm run build:remorse
npm run build:overdrive
npm run build
npm run auditions:build
npm run overdrive:smoke
npm run workspace:smoke
npx playwright install chromium webkit
REMORSE_TEST_PORT=5199 npm run test:e2e
npm run overdrive:e2e
```

Используй свободные изолированные порты; Форсаж по умолчанию проверяется на 5198. Запись `--list` не считается исполнением. Провал браузерного запуска — ограничение, а не успешная проверка. Не отключай падающие тесты, проверки безопасности или реальные правила ради зелёного отчёта; исправляй причину.

Проверь раздельные клиенты `games/chess/remorse/dist` и `games/chess/overdrive/dist`, совмещённый `dist`, сервер `dist-server/main.js` и auditions. Нужны реальные ответы на HTML, JS/CSS, оба Worker, GLB, аудио и шрифты; отсутствующий ресурс должен возвращать 404. Общие адреса — `/` для REMORSE и `/overdrive/` для Форсажа. У standalone-выхода собственный `index.html` находится в корне; используй соответствующую конфигурацию сервера из его README.

Проверь независимость данных, cookie, протоколов и исходных ресурсов. SDK не импортирует игровые правила; сервер не притягивает UI/React. Если меняешь миграционный код, сохрани прежние правила, оценку, версии, визуал и принятый звуковой банк REMORSE.

Если в окружении доступны независимые агенты, поручить `gpt-6.1-terra` с reasoning `high` отдельную живую приёмку на итоговой сборке. Она должна играть через UI, оценивать естественность RU/EN и понятность обучения, а не только читать тестовый отчёт. Если такой модели или доступа нет, прямо укажи это и выполни доступный реальный проход; не приписывай проверку Terra.

## 4. Полный проход Форсажа

Пройди реальным UI RU и EN, 3D и 2D. Не подменяй обычный проход вызовом внутренних функций. Контрольные позиции для редких сцен можно создавать локальными средствами QA, но не добавляй в production скрытый endpoint для подстановки позиции/энергии/результата.

Проверь девять уроков: ясность задачи до ограничения ввода, действие настоящими правилами, удержание объяснения до подтверждения, reload до/после подтверждения, переход к следующей позиции и оба финальных выхода. Пройди сохранённую обычную партию, повторный клик/тап/Escape, клавиатурные стрелки и Enter, выбор превращения и составной цели. Настройки языка и вида не начинают новую партию.

Сыграй полную тренировочную партию с реальным Worker. Проверь быстрые/долгие ответы, показ хода, минимум времени чтения результата, отмену при смене партии/режима и отсутствие старого ответа после reload/скрытия. Десять уровней имеют разные бюджеты; ≈400–2200 — предварительная внутренняя шкала, не подтверждённый человеческий Elo.

Проверь обычные ходы, шах/мат, рокировку, взятие на проходе, собственное и принудительное превращение. Для механик Форсажа проверь расход 5 на импульс, расход 10 на форму, три собственных хода с учётом активации, начисления +1/+2, ограничение энергии 10 и отсутствие повторной награды за тот же шах. Все шесть приёмов должны исполнять ядро, а не отдельную UI-логику.

## 5. Движение и оформление

Форсаж должен оставаться самостоятельным визуальным продуктом: синяя керамика, алюминиевое шасси, фарфор/кобальт, медные силовые детали, собственные силуэты и композиция. Не превращай его в перекрашенную REMORSE или универсальный dashboard. Устраняй наблюдаемые дефекты, сохраняя художественный замысел.

Просмотри **непрерывные сцены**, а не только один пик-кадр. Запиши локально все шесть приёмов, включение/окончание формы, обычное взятие, рокировку обоих флангов, оба вида превращения, шах и мат. Убедись:

- Подсечка двигает цель, а пешка остаётся на месте.
- Налёт проходит через клетку жертвы к пустому приземлению; жертва исчезает при контакте.
- Батарея проходит над заслоном без пересечения модели.
- Таран сначала доходит до цели; принудительно сдвигаемый конь скользит.
- Ротация разводит две фигуры встречными дугами.
- Прикрытие сначала освобождает королевскую клетку и затем заполняет её союзником.
- Рокировка не пересекает короля, ладью и пешки; в 2D внешний путь не обрезается.
- Пешка сохраняет свою модель до прибытия и затем меняется; форсаж меняет геометрию/материал силовой детали самой фигуры.
- Транзиентные эффекты полностью затухают, ввод не остаётся заблокированным, камера не теряет доску.

Повтори основные сцены с reduced motion и его переключением посреди движения, 3D/2D-переключением, новой партией и скрытием вкладки. Не должно оставаться старых таймеров, звуков или полупрозрачных фигур.

Размеры для проверки: ноутбук около 1440×900, телефон около 390×844 и горизонтальный телефон около 844×390. Главный экран игры должен помещать доску, обе строки игроков и текущее действие без прокрутки документа. Справка/история могут прокручиваться внутри. Проверь длинные имена, крупный текст, оба языка, меню и модальный фокус. Эмуляцию честно отделяй от физического телефона. FPS и производительность сообщай только если измерил, с указанием устройства/метода.

## 6. Два независимых сетевых клиента

Используй два отдельных профиля/контекста либо два устройства. Две вкладки одного профиля с общим cookie не являются двумя гостями. Запускай Node-сервер, а не один `vite preview`.

Создай комнату, передай приглашение, зайди вторым гостем, подтверди готовность с обеих сторон. Сыграй через UI обычные ходы, взятие и усиленный приём; сравни состояния и энергию обоих клиентов. Проверь отказ неверному месту/ревизии, повтор команды без второго применения, потерю ACK/связи, reload, переподключение и восстановление после перезапуска сервера с той же отдельной базой.

Проверь предложение/отказ/принятие ничьей, сдачу вне своей очереди, реванш с новым ID и сменой сторон. Восстановление снимка не должно повторять старые анимации и SFX. Новое сообщение готовности/ничьей не должно навсегда выключать ввод. Незавершённая команда не теряется молча и не исполняется дважды.

Отдельно проверь REMORSE на своей тестовой комнате: перенос чистого ядра и сервера не должен изменить реакции, сохранение или клиентский протокол. Не используй личную живую комнату владельца для QA.

Пройди также девять уроков REMORSE на RU и EN с обоими финальными выходами. Проверь последовательность «взятие → фактическая грань → реакция фигуры и правило → подтверждение → демонстрация», удержание объяснения после reload, сроки эффектов и возврат камеры. Через реальный UI проверь 3D и 2D, мобильные размеры, партию с браузерным ИИ, сетевой бросок и бонусный ход. Читай текст как новый игрок: причины, разрешённое следующее действие и подписи кнопок должны быть согласованы. Запиши отдельно, что исправлено, а что было проверено без изменений.

## 7. Звук и демонстрация с визуалом

Форсаж имеет 18 готовых оригинальных WAV, шесть разных звуков приёмов и общее расписание движения/аудио. Это авторский DSP-банк, не скачанный CC0-пакет. Принятые звуки REMORSE не изменяй.

Проверь реальный AudioContext после пользовательского жеста, загрузку всех файлов, последовательность расход → действие/контакт → превращение → доход → шах/результат, ограничение голосов, mute/громкость, скрытие вкладки и отсутствие позднего воспроизведения старого события. Проверки по возможности записывай в цифровой поток без вывода на динамики. Пики отдельных WAV не заменяют измерение суммарного микса.

Подготовь короткую последовательность «звук плюс визуал» для всех шести приёмов, активации, превращения, шаха и мата. Сохрани пригодные для просмотра записи локально; если в твоей среде можно действительно прослушать их без звука в комнате владельца, оцени различимость, характер и совпадение удара с изображением. Если слушать нельзя, прямо оставь субъективную слуховую оценку владельцу и предоставь воспроизводимые сцены. Не называй инструментальное измерение прослушиванием. На финальной вкладке звук включается владельцем вручную; системную громкость не меняй.

## 8. Итоговая сборка и одна вкладка

После исправлений повтори достаточные проверки именно финального head, не старой промежуточной сборки. Зафиксируй логический коммит и отправь в согласованную ветку без force-push; перед push получи актуальные изменения и сохрани чужую работу. Если работаешь в acceptance-ветке, подготовь PR к ветке кандидата, не сливая `main` автоматически.

Промежуточные законченные исправления тоже сразу фиксируй и публикуй в своей рабочей ветке. Это явное требование владельца: не копи всю приёмку до единственного большого push. После каждого этапа сверяй удалённый head и давай ссылку на коммит; незавершённые проверки перечисляй отдельно.

Оставь отдельный демонстрационный сервер. Из корня worktree после `npm run build`, при свободном 4185:

```sh
PORT=4185 HOST=127.0.0.1 \
DATABASE_PATH=./data/preview-remorse.sqlite \
OVERDRIVE_DATABASE_PATH=./data/preview-overdrive.sqlite \
npm start
```

Для телефона разрешён `HOST=0.0.0.0`; подставь фактический LAN-адрес и корректный origin. Не публикуй старый IP из истории как актуальный без проверки. Подтверди получение конкретного production JS и реальный ход по тем адресам, которые отдаёшь владельцу.

Только в конце открой одну видимую вкладку Форсажа по проверенному адресу. Не пиши «вкладка открыта», если инструмент её не открыл или доступ отсутствует. Активную REMORSE на 4173 не перезагружай. Демонстрация начинается с готового к игре экрана; путь к обучению, обычной партии, комнате и контрольным сценам укажи явно.
