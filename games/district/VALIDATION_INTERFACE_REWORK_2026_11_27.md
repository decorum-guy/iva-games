## Подтверждённый дефект приватности

До исправления автор сделки мог получить `target-resources`, если адресату не хватало скрытого ресурса. Теперь это объяснение доступно только самому адресату. Три регрессионные проверки сравнивают полные виды автора для двух скрытых рук одинакового размера, проверяют истечение и отсутствие предложения/истории у третьего участника. Получатель сохраняет точную собственную валидацию.

Прогнозы новостей продолжают раскрывать только опубликованные заголовок, стадию, зону и срок. Будущий скрытый исход и персональные последствия не добавлены в клиентскую проекцию. Публичный остаток банка сохраняет разрешённую точность `0 / 1 / 2+`.

### Торговля и карты — 12 сценариев

1. Встречный черновик → истечение в конце хода → reload → сохранённые количества → явное законное повторное использование → отправка с задержанным реальным ответом → принятие и точные балансы у обоих клиентов.
2. Живое встречное предложение сохраняет `parentId`; исходное получает `replaced`; обмен происходит после согласия выбранного адресата.
3. Потерянный ответ предложения восстанавливается из серверных условий; Retry не создаёт повторного предложения или ревизии.
4. Отказ виден обеим сторонам.
5. Отзыв виден обеим сторонам.
6. Банк показывает подтверждение и точные количества; обещание потраченного автором ресурса не принимается.
7. Потерянный ответ банка восстанавливается из истории; повтор не меняет руку второй раз.
8. Адресат видит собственную нехватку, автор не получает признак состава чужой руки.
9. Патруль ждёт подтверждения, затем переносит блокаду с причиной `patrol`; вторая активная карта в тот же ход недоступна.
10. Снабжение выдаёт ровно две выбранные единицы, включая одинаковый ресурс.
11. Подряд оплачивает две настоящие дороги; после этого возвращается обычная цена.
12. Купленная активная карта ждёт следующего собственного хода; Грамота объясняет уже начисленное скрытое очко.

Запросы с проверкой потерянного ответа выполнялись сервером реально: воспроизводитель задерживал или терял только доставку ответа, не подменял игровые данные. Для дорог использовались обычные `touchscreen.tap`, без `force`.

## Аудио и темп

Подготовлены **56 WAV: 11 действий и 45 поддерживаемых стадий 25 новостных семейств**. Реальные CC0 источники и процедурные слои указаны в [полной таблице](AUDIO_PLACEHOLDERS_2026_11_27.md); звуки шахмат и Colonist не использованы. Все файлы получены с `audio/wav`, проверены по SHA-256 и декодированы нативным Web Audio.

Технически подтверждены пользовательское разблокирование, ненулевой gain, остановка при mute, отдельные дом/дорога/улучшение/бросок/раздача/обмен, действия ботов и новая стадия E01. Poll, оба журнала и reload не повторяют прежний звук. Событие во время mute не догоняет после включения. Настоящий offline/online тихо восстанавливает исходную отметку; следующее новое предложение звучит один раз.

Шесть наблюдений действий ботов в расстановке: **861, 866, 1130, 953, 1190, 1188 мс**. Первое отсчитывается от начала наблюдения до первого действия, остальные — между наблюдениями. Это настоящие `Date.now()`/HTTP, опрос около 80 мс вместе с обычным UI-опросом 1100 мс; верхняя задержка от `scheduledAt` до наблюдения — **75 мс**. Точный timestamp исполнения отдельно сервером не записан. Обычный ход и длительность человеческой партии этим не измерены.

Ранее сохранённые 288 controlled-clock измерений сведены в [компактный отчёт](VALIDATION_TABLE_FEEDBACK_2026_11_27.md). Новое планирование: 650–1200 мс расстановка, 1000–4000 мс основные действия, редко 4200–4900 мс, 850–1500 мс конец хода; окно ответа человеку 20 секунд ограничено дедлайном. Сравнение с прежним циклом без пауз — по исходникам, не новый замер старой партии.

## Воспроизведение

```sh
npm ci
npm run check
npm run build:foundation
npx playwright install chromium
node scripts/district-interface-browser.mjs
node scripts/district-trade-browser.mjs
node scripts/district-audio-browser.mjs
node scripts/district-territorial-browser.mjs
```

Локальная среда не смогла скачать Playwright Chromium/WebKit с CDN (HTTP 403). Для описанных запусков использован отдельный Chromium из npm `@sparticuz/chromium` в игнорируемой `.qa/browser-runtime`, с обычными web security и многопроцессным режимом. Его исполняемый файл передавался через `PLAYWRIGHT_CHROMIUM_EXECUTABLE`; `PLAYWRIGHT_CHROMIUM_ARGS` поддержан для соответствующих скриптов. В GitHub CI устанавливается обычный Playwright Chromium. Пакет браузера не добавлен в зависимости продукта.

Полные логи, screenshots, аудиотрассы и тестовые базы остаются под игнорируемой `.qa`; Actions artifacts не публикуются. В репозитории находятся воспроизводители, лицензии и этот компактный отчёт.
