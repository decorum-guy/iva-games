# Карты «Района»: выбор и добавление

**Новое поручение после PR №17:** владелец отклонил квадратную карту и заказал три разные географии в 2.5D с перспективой десятков карт. [MAP_ART_DIRECTION](MAP_ART_DIRECTION.md) и [задание реализации](../../prompts/IMPLEMENT_DISTRICT_25D_MAPS.md) определяют переход. Он пока не реализован. Описание ниже документирует существующий профиль v0.2 и остаётся обязательным для его сохранений. Ограничение 5×5 не переносится автоматически на новый формат; новые правила соседства и события должны быть версионированы.

Поручение владельца от 26 ноября 2026 года: разные карты на выбор; новая карта создаётся по обычному описанию владельца и легко добавляется в GitHub. Это расширение содержимого поверх [правил v0.2](RULES_V0_2.md), а не неявная смена цен, сроков или числа игроков.

## Первый профиль

Правила — `district@0.2`, каталог — `district-maps@0.1`. Одна карта имеет собственные `id` и `version`. Исходная таблица из §2.1 правил сохранена как `crossroads@1`; другие карты переставляют клетки в том же профиле. Остальные правила, соседство по стороне, события и цели действуют без изменений. Событие перекопанной улицы выбирает одну из пяти строк выбранной карты.

| Карта | Отличие | Проверка баланса |
|---|---|---|
| Перекрёсток / Crossroads | Четыре квартала, нейтральные дома ближе к центру, парки по краям | См. текущий отчёт реализации; исходная спецификация сама по себе не подтверждает баланс |
| Бульвар / Boulevard | Нейтральные дома на углах, парковые площадки внутри кварталов | Новая гипотеза расположения |
| Два сада / Twin Gardens | Асимметричное расположение домов; другая ценность верхних и нижних участков | Новая гипотеза расположения |

Все три схемы: 5×5, 16 частных участков, четыре нейтральных дома, четыре площадки парков, одна площадь; 2–4 общих места. Симметрия не обязательна: участки не раздаются бесплатно по цветам, за них торгуются. Это не доказывает, что асимметричная карта сбалансирована.

## Формат

Каждый файл `maps/<id>.<version>.json` соответствует [map.schema.json](map.schema.json). Поля содержат только данные: название/описание на RU/EN, размеры, строки клеток и поддерживаемый состав. Скрипты, HTML, URL ресурсов и правила внутри карты не допускаются.

Символы: `.` — частный участок банка; `H` — нейтральный дом; `P` — незавершённая площадка парка; `S` — площадь. Строки идут сверху вниз; координаты A1–E5 вычисляются автоматически. Пример — [crossroads.1.json](maps/crossroads.1.json).

Каталог автоматически читает все `maps/*.json` при сборке. Новый файл не требует отдельной записи в интерфейсе или серверном списке. Сервер проверяет настройки комнаты; старт сохраняет полный снимок карты и её идентификатор/версию. Начатый матч продолжает жить со своим снимком. После старта карта не меняется.

Опубликованную версию не редактируют и не удаляют: исправление расположения или описания выпускается новым файлом, например `boulevard.2.json`. Обновление только каталога не меняет версию экономики; изменение правил требует отдельной версии и совместимости сохранений. В первой версии карты — доверенное содержимое репозитория, не загрузка произвольного JSON игроками.

## Как добавить по описанию владельца

1. Переведи описание в композицию клеток действующего профиля, дай короткое имя и объясни игровой замысел. Если описание просит реку, мост, аренду или шестое место, отдели визуальный мотив от новой механики: данных нынешнего формата для таких правил недостаточно.
2. Добавь один JSON с новым `id` и версией `1`. Для новой редакции существующей карты сохрани старый файл и увеличь `version`.
3. Запусти `npm run district:maps`, затем `npm run district:test` и `npm run build:foundation`. Сравни с базой PR через `npm run district:maps -- --base <base-ref>`, чтобы не перезаписать уже опубликованные версии.
4. Проверь появление карты в комнате, читаемость превью, старт с выбранной картой и восстановление сохранённой партии. Прогони воспроизводимые партии на 2, 3 и 4 места. Изменение геометрии может менять выгоду построек и целей.
5. Запиши фактические результаты, опубликуй отдельный коммит/PR без force-push. Установка на production происходит через принятый процесс выпуска, не от самого наличия файла на GitHub.

Готовое задание для агента — [ADD_DISTRICT_MAP](../../prompts/ADD_DISTRICT_MAP.md). Полезный запрос владельца: «Сделай карту с плотным жилым верхом и двумя зелёными дворами снизу, чтобы за разные части района торговались по-разному». Агент создаёт данные, проверяет и публикует их; владельцу не требуется вручную редактировать JSON.

## Что проверяет валидатор

Формат и неизвестные поля, RU/EN, размеры/символы, состав клеток, уникальность `id@version`, поддерживаемый состав. Дополнительно проверяются необходимые геометрические условия целей: места у парков, участки без соседних нейтральных домов, возможность соседства двух частных участков. Это **структурная проверка**, не доказательство достижимости всех стратегий в конкурентной партии, равенства целей или интереса игры.

Расширенный профиль с большим полем, 5–6 местами, новым ландшафтом или зданиями вводится отдельно после проработки Gemini/владельца и проверки темпа. Формат заранее не выдаёт такую карту за совместимую с v0.2.
