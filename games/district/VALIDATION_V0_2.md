# «Район» — первый исполняемый прототип и проверки

26 ноября 2026 года. Работа в `feat/district-first-playable`, [PR №16](https://github.com/decorum-guy/iva-games/pull/16), поверх PR №15. Основание — прямое поручение владельца начать игру, добавить выбор карт и закрепить роль основного веб-агента. Предложения Gemini ещё не применялись.

## Реализация

`@iva-games/district`: чистое версионированное ядро, приватные представления, обычные алгоритмические боты и отдельный серверный `/runtime`. Правила `district@0.2`; каталог карт `district-maps@0.1`; снимок выбранной карты, состав, случайные результаты и бот-профили сохраняются в матче. Нормативные значения экономики и сроки v0.2 сохранены. Карты — отдельные автоматически подхватываемые JSON; исходная геометрия сохранена как `crossroads@1`.

Реализованы все фазы v0.2, банк, резервирование и атомарные сделки/встречные условия, парки со взносами и подписями, закрытые ставки, развитие, одновременный доход, шесть целей и итоговый капитал. Обрыв связи не заменяет человека стратегическим ботом. Явный выход и возврат отдельные; уход последнего человека фиксирует `abandoned` до вызванных выходом автоматических ходов.

Runtime использует отдельные таблицы `district_*` в существующей базе сессий; таблицы lab не меняются. Команда, состояние и ответ сохраняются транзакционно. Повтор с тем же ID возвращает прежний ответ, чужой доступ и конфликт содержимого отклоняются. Политика получает только разрешённый вид, вычисляется вне SQL-транзакции и повторно проверяется перед записью. Платформенная сверка двигает сроки и ботов без открытого браузера.

В портале есть выбор/превью карты, 2D SVG-поле, все игровые действия, история, краткие правила и результат на RU/EN. Это справка, а не интерактивное обучение. После неизвестного ответа повторяется тот же конверт команды. Для телефона предусмотрены адаптивная верстка и переход к текущим действиям.

В первом совмещённом запуске тестов, сборки и браузера неизменённый тяжёлый тест геометрии REMORSE превысил 5 секунд: 873/874 прошли. Повтор полной тестовой группы отдельно, с четырьмя workers, дал 874/874. Исходники и таймауты шахмат ради этого не менялись. Первый опубликованный этап карт имел ESLint-замечание к control-character regex; валидатор исправлен без изменения его правила.

Браузер по умолчанию в среде отсутствовал, а стандартная загрузка дала 403. Для проверки использован временный Chromium 158.0.8127.0 из `@sparticuz/chromium 158.0.0`, установленного вне зависимостей проекта в игнорируемую QA-папку. Он не добавлен в lockfile. Снимки desktop/mobile просмотрены; найдены и исправлены имена select для доступности и перенос текста цели. Реальная браузерная проверка backend не подменяет API ответами.

## Воспроизводимые синтетические партии

Команда: `npm run district:simulate`. Это **108 настоящих исполнений игрового ядра**, не придуманные примеры: три карты × три состава (2/3/4) × три группы политик × четыре seed. Один человеческий слот управляется программной политикой через обычные действия; остальные — бот-слоты. Синтетический человеческий контроллер ведёт такие же локальные ограничения инициатив. Авторитетное состояние не подменяется, правила не ускоряются; часы испытания виртуальные.

Seed решений отделён от seed правил (`district-policy-smoke-v1`). Политики не получают колоду, чужие цели/резервы или ставки. Каждый переход проверен инвариантами; каждые 17 переходов состояние проходило JSON-сохранение/чтение. Затем весь журнал воспроизведён заново с проверкой точного хеша каждого состояния.

- **108/108** партий завершились обычным результатом.
- **11 351** переход проверен и **11 351** повторно воспроизведён без расхождений.
- **13 641** вызов политики; в этих матчах не потребовался переход по дедлайну. Таймауты проверены отдельными тестами, а не выдаются за покрытие этой серии.

## Что ещё не принято

Живой плейтест с владельцем/друзьями; баланс по человеческим стратегиям и длительность настоящих переговоров; физический телефон; полноценное интерактивное обучение; финальный рисунок/анимация/звук; 3D; 5–6 мест; интеграция результатов Gemini. Реальные Telegram-сообщения не отправлялись. Производственный сервер, DNS и main в этом этапе не изменялись.

Первая локальная приёмка — [ACCEPT_DISTRICT](../../prompts/ACCEPT_DISTRICT.md). Карты добавляются по [MAPS](MAPS.md). После принятого прототипа предложения Gemini оформляются отдельной редакцией и проверяются тем же воспроизводимым набором, а не безусловно заменяют текущие правила.
