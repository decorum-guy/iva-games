## Реализация и ассеты

В коде есть авторитетное ядро трёх карт, стрельба, инструменты, строитель, дроны, личная экономика, строительство, питание, станции, транспорт, разгрузка, возрождение, фильтрация видимости и исходы операций и матча. Клиент поддерживает RU/EN, 3D/2D, клавиатуру, pointer и touch, семь отдельных уроков и возврат в сохранённую партию. Общий runtime использует SQLite, admission с Ed25519, одноразовые билеты, поколения управления, долговечные receipts/outbox и архивы точных версий runtime/client.

Реализованы durable FIFO, 15-секундные reservations, один ожидающий старт на хозяина, admission по ресурсам и ограниченное объединение FULL-коммитов. Без принятого измеренного профиля действует лимит одной комнаты. Синтетический диагностический профиль не разрешён в production и не подтверждает мощность VPS.

Собственный комплект: **151 арт-файл**, 52 GLB стандартной и облегчённой детализации, 29 WAV, 50 SVG-иконок, 8 эффектов, обложка, 3 превью карт и 3 локальных лицензированных шрифта. [Реестр](art/ASSET_REGISTER.md) содержит генераторы, происхождение, лицензии и проверки. Все 52 текущих GLB импортированы в Blender и осмотрены на статическом листе: в одном ракурсе явных пропавших частей или крупных отверстий не обнаружено. Это не финальная оценка заполненной игровой сцены и анимации. Прослушивание не выполнено.

## Нагрузка, производительность и открытые дефекты

**SERVER_BUSY не исправлен.** Трасса R6 FP01/2D связала triggering tick 472 с commit RPC 252 / span 473 / batch 222: worker — 0.541 ms, RPC — 1756.874 ms, queue — 2.117 ms, writer execution — 1754.367 ms, reply — 0.287 ms, backlog — 1757.066 ms. Максимум SQLite transaction 1754.317 ms соответствует длинному execution. В браузере 2D наблюдались интервалы ≈16.7 ms и 0 LongTasks. В трассе 474 строки; trigger полностью сохранён, одна `consumeBridge` оставалась pending. [Разбор трассы](qa/ci-round-6.json). Отдельный вклад fsync, locks, SQL и scheduling не установлен. Cumulative checkpoint max 1617.086 ms не связан по времени с конкретным tick.

Отдельное задание R6 storage на другом runner: commit p99/max — 1.793/3.485 ms без trace, 20.693/94.428 ms под trace; измеренный writer fsync max — 92.973 ms. Разницу нельзя целиком приписать tracer, а эти измерения нельзя переносить на задание карты. FULL, publication barrier, 30 Hz и backlog guard не ослаблялись.

Историческое ядро R6 `14d49d29954d0f7f427feea026beb23113699ff8ecb36ec4480f61f339a61e68`: 62 целевых теста, 2556 byte-equal World и 468 safe views; пять технических серий, 360 матчей, последняя серия — 72/72 без `technicalErrors`. Строгий R6 maximum-scene gate с 500 samples / 30 warmup прошёл с p99 **4.847924/3.089975/3.061874 ms**. Ранее полученный локальный FAIL при 17.939 ms сохраняется в истории. Это не проверка баланса людьми и не подтверждение production capacity.

**Час нагрузки не пройден.** Первые две реальные попытки остановились после 379.228 s и 1084.328 s / 14 матчей с `overloadPause`. R4/R5 остановились до Docker; workload — 0. Третья попытка, R6, реально приняла 4 комнаты при 2 CPU / 2 GiB / swap 0 и остановилась через **389.063260 s из 3600**: 4 технических матча, 8 стартов, pauses — 0. Коды отказов: `OBSERVER_DISCONNECTED`, `SERVER_HEALTH_FAILED`, `DRAIN_FAILED`. Общий счётчик `failRoom`, равный 4, не доказывает 4 ошибки SQLite I/O. Исходное исключение не опубликовано; причина неизвестна. До отказа: stepWork p99 — 3.6 ms, commit p99 — 13.8 ms / max 31.662 ms, CPU headroom ≥53.41%, memory peak headroom ≥64.58%.

**Default 3D медленный на SwiftShader:** в R6 frame p50 ≈167–267 ms. Измеренные синхронные интервалы camera/entity/effects/render-submit не объясняют остальную задержку. React render/commit, async model completion и GPU completion полностью не измерены; точная причина не установлена.

**Приёмка потери фокуса открыта.** Оба headed-браузера R6 фактически оставались visible/focused. В Playwright обнаружен внутренний focus override. Принятая отдельной CDP session команда `false` перед navigation не доказывает снятие всех overrides. Новый Chromium fixture использует публичный `noDefaults` и собственный default context; нового запуска ещё нет. Для stock WebKit публичный способ отключения не найден.

## Следующий кандидат — не принятый R7

Отдельный ограниченный SQLite probe воспроизвёл allocated-WAL latch после **искусственно удержанного reader**: после release операция PASSIVE перенесла все 16,334 frames, `quick_check=ok`, но WAL размером 67,296,112 bytes всё ещё отвергался прежним guard на 64 MiB. Диагностический SQLite TRUNCATE освободил WAL и сохранил 4 world hashes. Native reclaim реализован на отдельном соединении с `busy_timeout` 0; FULL и hard limit неизменны. Повтор побайтно того же сценария подтвердил автоматическое освобождение WAL до ручного контрольного TRUNCATE, сохранение четырёх world hashes и journal sequences. [Проверка и границы](../../docs/iva-games/REALTIME_WAL_RECLAIM.md). Это **не атрибуция отказа R6 hour** и не исправление browser stall на 1754 ms.

Добавлены фиксированные counters первых причин и этапов `failRoom` без raw exception, stack, IDs или world. Legacy `storageFailures` сохранён. Контролируемые 15 publication tests и 26 проверок Node-harness — PASS, включая redaction, first failure, no-double-count и stale authority. Это диагностика следующего кандидата, а не восстановленная причина завершённого R6.

D31 terminal-phase guard входит в R6 runtime: задержанный commit для finished/abandoned/pendingOutcome больше не заменяется overload pause. Контролируемая задержка confirmation на 1500 ms воспроизвела 3 FAIL до правки; 11 publication tests прошли после неё, running-overload guard сохранился. Native network/image tests прошли. Паузы на подготовке этим не объясняются.

После отдельного аудита собственных доставок исправлен персональный зачёт: он использует тот же список живых незащищённых бойцов/дронов в круге, что и командная разгрузка. Урок отряда дополнительно требует настоящей самостоятельной доставки дроном после возвращения к бойцу; финальный урок — доставки бойцом в тактике и результата операции. При неудачном окончании показан повтор. Ранее завершённые сохранённые уроки сохраняют статус. Новые тесты на старом коде дали **5 FAIL / 44 PASS**, после применения — **49/49 PASS**. [Исходный повтор](qa/own-delivery-regression-r7.json).

Полный map E2E теперь заказывает док/дронов и возобновляет приказы новым подразделениям через UI, требует наблюдаемой собственной автономной разгрузки того же транспорта, положительных командного и личного счётов, правильного результата и запуска новой комнаты. Состав 1v1 с normal-ботом и правила не упрощены. Прежний R5 PASS с нулём доставок сохраняется как историческое прохождение по прежнему набору проверок; новые условия ему не приписаны.

## Непринятые обязательные области и доступ

Не приняты все 3 карты до результата через UI, собственная доставка в полноценном матче, повтор партии, все состояния 64 групп UI, privacy в pixels/effects/audio/statistics, физический телефон, прослушивание, настоящая потеря IP-пакетов, 24 h wall-clock recovery и production backup/restore. Прежние 14 controlled TCP-delay profiles и обрывы на 1/5/8/15 s привязаны к своим старым артефактам.

Cloud browser не видит loopback изолированной команды. Запрос outside-sandbox listener был автоматически отклонён политикой **sandbox_approval:false**. Chromium wrapper не содержит binary; стандартный Playwright install вернул 403. Обхода ограничений не было. Результаты CI-browser приведены отдельно от отсутствующего собственного прохождения.

Для третьего публичного сервиса нужна host integration. Административный SSH-доступ не установлен; существующий ForceCommand не предоставляет provisioning realtime/Caddy/keys/volume. Права не расширялись. Two-image deploy и fixture ACTIVE не подтверждают выпуск. Требуются реальные DEPLOYED/digest и публичная UI-проверка; их нет.
