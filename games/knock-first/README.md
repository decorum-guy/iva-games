# «Сначала постучи» / Knock First

Пакет `@iva-games/knock-first`: кооперативная игра от первого лица для комнат
на 2–5 мест, с явными ботами, тремя маршрутами и отдельным учебным отсеком.
Правила заданы в [SPEC.md](SPEC.md); фактические ревизии, результаты проверок,
дефекты и состояние выпуска фиксируются в [STATUS.md](STATUS.md).

**Текущая граница приёмки: 0 полных циклов в реальном браузере.** Фактического
прослушивания, проверки на физическом телефоне и производственного выпуска
этой игры нет. После нового прямого разрешения владельца вход локального
стенда успешно открыт в Chromium; проверены RU/EN и выбор параметров миссии,
найдены, исправлены и перепроверены четыре визуальных дефекта входа. Это ещё не игровая приёмка. Автоматические тесты, расчёты ригов
и Blender-рендеры не являются браузерной приёмкой или подтверждением готовности
к выпуску. За доказательствами и дальнейшими изменениями статуса обращаться
к журналу, а не трактовать наличие сборки как закрытую приёмку.

Текущая браузерная граница: защищённый инструмент входа возвращает
`locator_invalid` для найденных видимых полей; отдельный профиль недоступен
через интерфейс управляемого Chromium, Incognito отключён. DevTools также
запрещён политикой среды. Это наблюдаемые ограничения инструментов,
не ошибки игры; обходы этих ограничений не выполнялись.

## Архитектура

Пути в таблице относятся к этому каталогу, если не указан корень репозитория.

| Область | Где находится и за что отвечает |
| --- | --- |
| Чистое ядро | `src/core/mission.ts` — состояние, команды, боты, Слушатель, переноска, помощь и исход; `level.ts` — маршруты и учебный отсек; `geometry.ts` — движение и столкновения; `acoustics.ts` — распространение звука через порталы, двери и канал |
| Контракты | `src/core/types.ts`, `version.ts`, экспорт через `src/index.ts`; версии правил, контента, сетевого payload и бота закрепляются за комнатой |
| Авторитетный runtime | `src/runtime.ts` — `KnockRuntime`, шаг 30 Гц, персональное представление игрока, проверка команд, SQLite checkpoints/receipts и восстановление; аренда владельца препятствует одновременному управлению одной миссией двумя процессами |
| Интерфейс | `src/client/KnockFirst.tsx`, `Lobby.tsx`, `copy.ts`, `knock-first.css` — вход, настройки комнаты, RU/EN, HUD, урок, результат и настройки доступности |
| 3D, ввод и звук | `src/client/Scene.tsx` связывает React со сценой; `scene.ts`, `materials.ts`, `rig.ts`, `controls.ts`, `audio.ts` реализуют Three.js, эхо, IK, управление и Web Audio |
| Сетевой клиент | `src/client/network.ts` — снимки, ввод, переподключение и повтор неподтверждённых команд с прежним `actionId`; сервер определяет события, скрытое состояние и итог |
| Интеграция платформы | От корня: `apps/platform/src/main.ts` регистрирует runtime; `apps/portal/src/App.tsx` подключает вход `/games/knock-first` и компонент комнаты; `apps/portal/vite.config.ts` раздаёт и копирует локальные ресурсы |

Используются существующие аккаунты, сессии, друзья и комнаты Iva Games.
Собственной системы регистрации или отдельного списка сетевых комнат у игры
нет. Общий транспорт **`iva-live@1`** переиспользован из опубликованного
[PR #42](https://github.com/decorum-guy/iva-games/pull/42): контракт находится
в `packages/session-kit/src/realtime.ts`, а проверка сессии, состава комнаты
и WebSocket-шлюз — в `apps/platform/src/realtime.ts`. Подробности —
[REALTIME.md](../../packages/session-kit/REALTIME.md).

Клиент подключается к `/api/platform/v1/rooms/<roomId>/live` с обычной сессией
платформы. Снимок персональный; клиент не получает полное скрытое состояние
миссии. Локальный `LiveGameSession` в runtime служит адаптеру и детерминированным
тестам и не вводит второй публичный транспорт.

## Команды из корня репозитория

Использовать поддерживаемую корневым `package.json` версию Node.js и установленные
зависимости workspaces.

| Команда | Назначение |
| --- | --- |
| `npm run knock-first:test` | Тесты ядра, маршрутов, runtime, сохранений, сети и клиентских модулей; нагрузочный файл исключён |
| `npm run knock-first:load` | Отдельный автоматический сценарий шести комнат по пять мест с настоящими HTTP/WS и SQLite; отчёт в `.qa/knock-first/network-load.json`, без браузерного прохождения |
| `npm run knock-first:assets:check` | Структура конечных GLB, анимации и skin, аудиосигналы, шрифты и ссылки на текстуры; нужны Python-зависимости из `assets-src/requirements.txt` |
| `npm run build:all` | Общая сборка репозитория, включая platform и portal; само по себе не выпускает игру |

Тесты лежат в `tests/`, конфигурации — `vitest.config.ts` и
`vitest.load.config.ts`. Сетевые fixtures используют штатные сервисы платформы
и отдельные тестовые хранилища. Область проведённых проверок и их результаты
следует читать в `STATUS.md`, а не выводить из имён тестов.

## Изолированный локальный стенд

Для этой ветки выделены **backend 4358** и **portal 5358**. Ниже приведены
существующие параметры `apps/platform/src/config.ts` и Vite. Команды описывают
локальный запуск; вход этого стенда действительно открыт в браузере.

Первый терминал, из корня репозитория:

```bash
npm run build:platform
NODE_ENV=development PLATFORM_HOST=127.0.0.1 PLATFORM_PORT=4358 \
PORTAL_ORIGIN=http://127.0.0.1:5358 \
PLATFORM_DATABASE_PATH=.qa/knock-first/platform.sqlite \
PLATFORM_LAB_DATABASE_PATH=.qa/knock-first/runtime.sqlite \
MAIL_MODE=file MAIL_FILE_DIRECTORY=.qa/knock-first/mail \
node dist-platform/main.js
```

Второй терминал, также из корня:

```bash
IVA_PLATFORM_TARGET=http://127.0.0.1:4358 \
npm --prefix apps/portal run dev -- --port 5358
```

Вход стенда — `http://127.0.0.1:5358/games/knock-first`. Vite проксирует
`/api/platform`, включая WebSocket, на 4358. Вход в аккаунт проходит штатным
платформенным потоком; `MAIL_MODE=file` сохраняет письма локально. Платформенные
аккаунты/комнаты и состояние миссий хранятся в разных SQLite-файлах выше.
`PLATFORM_LAB_DATABASE_PATH` — фактическое имя общей настройки runtime-хранилища;
игра создаёт в нём собственные таблицы `knock_*`.

`.qa/` игнорируется Git. Базы, письма, логи, отдельные браузерные профили и
проверочные изображения стенда должны оставаться внутри `.qa/knock-first/`.
Другие рабочие деревья и их порты/базы не используются.

## Ресурсы и воспроизводимость

`public/knock-first/` содержит локальные GLB, PBR-атлас, WAV, SVG, шрифты и
обложку; внешних runtime CDN для этих ресурсов нет. GLB используют общие
текстуры по относительным ссылкам, поэтому копируется весь каталог.

Производство, точные метрические контракты и проверенные лицензии описаны
в [ASSETS.md](ASSETS.md), происхождение и SHA-256 каждого файла —
в [assets-manifest.json](assets-manifest.json). Исходники сохранены
в `assets-src/`; модели воспроизводятся Blender-скриптом, медиа — Python-скриптом.
`npm run knock-first:assets` запускает только `generate_media.py`; полный
последовательный конвейер моделей, обложки и обновления манифеста приведён
в `ASSETS.md`.

Модели, материалы, звуки и знаки созданы для проекта; запись
`Original-project-asset` фиксирует происхождение и не назначает владельцу
новую публичную лицензию. IBM Plex Mono и PT Sans поставлены с исходными
уведомлениями SIL OFL 1.1 и сохранёнными TTF. Рассмотренные сторонние наборы
перечислены отдельно; их модели и звуки в поставку не импортировались.
